思考了 27s

我赞成单独加一档 Discovery Skills，而且这次我觉得我们抓到了一个真正不同的问题：
Research Skills 教模型“已知该怎么研究时，把研究做得更好”；Discovery Skills 教模型“现有研究框架里没有答案时，怎么主动找到新的东西”。

这不是同一类能力。
而且外部资料支持这个区分。Google Co-Scientist 的 Generation / Evolution 里专门有 research expansion、iterative assumption identification、combination、simplification、analogies、out-of-box thinking 等，就是在显式给模型施加“发现算子”，而不是指望基础模型凭空灵光一现。arXiv 还有研究直接指出，当前生成式 AI 一个明显短板就是不擅长从异常实验结果里产生真正新的 hypothesis——它容易在已有知识表示里做类比式增量推理，而不容易像人一样抓住 anomaly 后改框。Nature
所以我认为这档非常有必要。
我会先定义 Discovery Skill 的目的
不是：
generate more ideas.

而是：
主动离开当前 solution basin，制造新的 mechanism、representation、question 或 explanatory frame。

也就是说普通 research-expansion 可能告诉它：
现在方向太窄了，扩。

Discovery skills 则告诉它：
具体有哪些成熟的方法可以把“不同”造出来。

这就像 Codex 的 brainstorming 不是说“发挥创造力”，而是真的给 brainstorm 方法。
第一批我会给 8 个 discovery skills
1. anomaly-driven-discovery
这个我认为必须排第一。
什么时候用
出现：
- residual；
- outlier；
- 某些数据始终解释不了；
- 预测总体对，但某个局部系统性偏离；
- 一个失败结果与当前模型矛盾。
方法
不要第一反应把 anomaly 当 noise 清理掉。
先问：
1. anomaly 是否稳定复现？
2. 它依赖哪些变量？
3. 哪个已有 assumption 若错，正好会产生这种 pattern？
4. 当前模型解释不了它的最小部分是什么？
5. 能否建立一个新 mechanism，同时解释正常区域 + anomaly？
6. 什么实验能区分 artifact 与新现象？
这是真正的 discovery 方法。
而且我特别想要这张，因为模型现在天然容易把异常解释掉，而不是从异常里发现东西。Nature
2. representation-shift
非常重要。
很多突破并不是：
在当前解法里想到更聪明的一招。

而是：
换一种问题表示以后，原问题突然变简单。

比如 OMILREC：
原来大家想：
FCN 每次 evaluation 怎么更快？

新的 representation：
为什么要 evaluation 这么多次？

再换：
四个 Minuit stage 是不是必须这样组织？

再换：
这到底是 optimization problem，还是可以 surrogate / reformulate？

Skill 就直接教：
当一个问题长期在同一个对象层次上优化时，系统试几个表示：
- variable representation；
- objective representation；
- data representation；
- algorithmic abstraction；
- spatial vs frequency；
- local vs global；
- continuous vs discrete；
- per-operation vs whole-process；
- component vs system。
然后问：
原来的瓶颈在新表示下还是瓶颈吗？

我觉得这张对“突破”特别重要。
3. assumption-inversion
和现在的 assumption-audit 不一样。
Audit 是：
这个 assumption 对不对？

Discovery 是：
如果我故意把它反过来，会出现什么世界？

例如：
大家都优化 FCN cost
→ 假设 FCN cost 根本不是问题

大家默认固定 architecture
→ 假设 architecture 本身可以换

大家认为约束 A 必须固定
→ 假设 A 可以放开，真正必须保持的是更底层量 B
具体方法可以直接是：
- fixed → variable
- variable → fixed
- local → global
- deterministic → stochastic
- optimize → eliminate
- estimate → measure
- reconstruct → classify / retrieve / approximate
- constraint → objective
- objective → constraint
这种 operator 很容易真正造出不同方向。
Google Co-Scientist 的 iterative assumptions identification 和 Evolution 本身就在利用这种思路。arXiv
4. cross-domain-analogy
Google Evolution agent 明确包含 analogy / inspiration from existing hypotheses。arXiv
但这个 skill 不能写成：
“去其他领域找灵感。”

要教结构类比。
方法：
先抽象当前问题：
对象是什么？
约束是什么？
输入输出关系是什么？
瓶颈是什么？
什么东西需要被估计/搜索/优化？
然后 Searcher 可以并行去找：
“其他领域有没有同样结构的问题？”

最后不是直接搬 solution，而是写映射：
领域 A              当前问题
state               ↔ reconstruction parameters
likelihood search   ↔ optimization
cached surrogate    ↔ ?
...
映射成立才迁移机制。
这对真正跨领域 discovery 很关键。
5. hypothesis-recombination
这个直接有 Co-Scientist 先例：Evolution agent 会从高排名 hypotheses 获得 inspiration，直接 combination、simplification，再产生新的 hypothesis。arXiv
方法可以很机械但有用：
拿两个部分成功的方向 A/B：
- A 的 mechanism + B 的 representation；
- A 的 observation + B 的 explanation；
- A 的 algorithm + B 的 constraint handling；
- 删除 A 中不必要部分；
- 把 A/B 提升到共同的更高层 mechanism；
- 找“为什么 A 在区域 X 有效、B 在 Y 有效”，构造统一方案。
关键是：
不是平均拼装，而是找互补结构。

6. contradiction-mining
这个我觉得特别科学。
触发：
两个可信结果彼此不兼容。

普通 agent 容易：
- 选一个；
- 平均；
- 说“可能都有道理”。
Discovery scientist 应该想：
矛盾本身是不是新信息？

方法：
Result A says X
Result B says not-X
先找：
- 条件哪里不同；
- hidden variable 是什么；
- 是否存在 regime transition；
- 两者是否其实测的是不同 latent quantity；
- 什么新模型能让 A/B 同时成立？
科学史里很多新机制就是从“两个都对但看起来冲突”出来的。
这一张和 cheapest-discriminating-experiment 也能很好配合：
contradiction-mining 造新解释，discriminating-experiment 决胜。

7. search-the-negative-space
这个和 research expansion 有区别。
Research expansion 是：
多产生方向。

Negative-space discovery 是：
系统问“大家没研究什么？”

Google Co-Scientist 的 Research Expansion 明确会看已有 hypotheses 和 research overview，寻找此前未探索的 hypothesis-space 区域。arXiv
可以直接教：
先画已有搜索空间：
大家改变过什么？
大家始终没改变什么？
所有方法共同保留了哪些假设？
哪些组合从来没出现？
哪些区域因为历史原因根本没被试？
然后优先检查：
所有方案共同不变的东西。

因为突破经常藏在那里。
OMILREC 就很典型：
如果所有 agent 都在：
“怎么把 FCN 写快”

那么 negative space 就可能是：
“为什么我们一定要执行这些 FCN evaluations？”

8. question-reframing
这是最上层的一张。
不是：
找新答案。

而是：
重新问一个更有生产力的问题。

方法：
当前问题：
How do we make X faster?

试着重写成：
- Why is X needed?
- What determines the number of X?
- What information is X estimating?
- Can that information be obtained another way?
- What would make X irrelevant?
- What is the actual scientific objective behind X?
物理分析同理。
原问题：
为什么 phase-by-phase nonlinearity 漂了？

可以重写：
哪些 detector-response degrees of freedom 能产生 geo-neutrino observable 的这种变化？

问题一换，研究空间就完全不同。
我觉得这张是 Scientist 与普通 Executor 最可能拉开差距的地方。
于是现在 Skills 可以非常自然地分三档
这次我觉得不是为了分类而分类，而是用途真的不同：
Task Method Skills
“这类科研总体怎么干。”
program-optimization
physics-analysis
data-analysis
ml-research
...
Research Skills
“科研过程中的常见工作怎么做好。”
measurement-discipline
knowledge-gap-search
assumption-audit
critical-validation
cheapest-discriminating-experiment
...
Discovery Skills
“当前已有套路里没有答案时，怎么主动产生新的发现空间。”
anomaly-driven-discovery
representation-shift
assumption-inversion
cross-domain-analogy
hypothesis-recombination
contradiction-mining
search-the-negative-space
question-reframing
我觉得这三档非常自然。
Discovery Skills 和 10 个 Proposer 也能很好结合
比如 Scientist 卡住：
当前方向都差不多。

加载：
research-expansion
它决定：
我要买 breadth。

然后不一定只是：
“请 10 个 Proposer 自由想想。”

而是可以把 discovery methods 作为不同生成元：
P1 → representation shift
P2 → assumption inversion
P3 → cross-domain analogy
P4 → anomaly-driven
P5 → negative-space search
P6 → question reframing
P7 → recombination
P8 → contradiction mining
...
这才真正解决我们以前一直担心的：
10 个 fresh Scientist 看同一个世界，最后全想到同一个 hotspot。

不是靠随机 temperature 制造 diversity。
而是：
给不同研究者不同的 discovery method。

Google Co-Scientist 其实就是这么做的：Generation/Evolution 不只 brute-force 生成大量 hypotheses，而是用了 literature exploration、scientific debate、assumption decomposition、research expansion、grounding、combination、simplification、out-of-box 等不同 reasoning biases。arXiv Google 也明确强调它不是单纯靠海量随机生成撞出几个好想法，而是通过 scientific reasoning priors、debate、evolution 等机制迭代提高 hypothesis 质量。arXiv
这跟我们要的其实非常接近。
而且这让我对 SimpleEvolution 之前那个“生成元”重新有一个更清楚的理解：
生成元本身就可以是 Discovery Skill。
以前我们说 G1–G9，有点像为了 diversity 人工给不同视角。
现在可以更扎实：
每个 generator = 一种经过文献/实践沉淀的 discovery method。

那么 tree 上的 mutation 不再是：
“随机换个 persona。”

而是：
对当前研究状态施加不同的科学发现算子。

这个我觉得会比我们早期的 G1–G9 设计强很多。
所以 Discovery 这一档我非常支持，而且我会把它看成比普通 Research Skills 更值得做研究本身的一层——因为“会规范地做科研”现在强模型已经不弱了，真正难的是：
如何稳定地产生改变问题结构的发现。

这也是现有 AI scientist 仍然远没有解决好的地方。Nature

总结一下discovery skill和skill共享的事情













可以，收束成一个很简单的设计。
Discovery Skill 是什么
前面的普通 research skills 解决的是：
科研这件事怎么做得规范、有效。

比如：
- measurement discipline
- assumption audit
- cheapest discriminating experiment
- critical validation
- knowledge-gap search
而 Discovery Skills 解决的是另一个更难的问题：
当现有思路不够时，怎么主动制造新的解释、新机制、新表征、新问题和突破方向。

第一批可以包括：
- anomaly-driven-discovery：从异常、残差、解释不了的现象里找新机制
- representation-shift：换一种问题表示，跳出当前优化对象
- assumption-inversion：把默认假设反过来，看是否打开新世界
- cross-domain-analogy：从结构相似的其他领域迁移机制
- hypothesis-recombination：组合、简化、变异已有部分成功方向
- contradiction-mining：把互相矛盾的可信结果当成发现入口
- search-the-negative-space：系统寻找大家一直没改、没试、没问过的地方
- question-reframing：不再找新答案，而是重新问一个更有生产力的问题
它们本质上就是科学发现方法论，而且可以直接借鉴 Google Co-Scientist 的 generation / evolution / research expansion 等做法，不需要自己凭空发明。
Discovery Skill 和 Research Expansion 的关系
两者不要混。
research-expansion 回答：
现在需要扩大搜索空间，怎么展开？

Discovery Skills 回答：
具体用什么方法制造真正不同的方向？

所以 Scientist 卡住时可以：
research-expansion
    ↓
决定需要 breadth
    ↓
开多个 Proposer
    ↓
分别给不同 discovery method

P1 → representation-shift
P2 → assumption-inversion
P3 → cross-domain-analogy
P4 → negative-space
P5 → question-reframing
...
这样多开 Proposer 不再是“同一个问题采样十次”，而是对研究问题施加不同 discovery operators。
这也可以替代以前比较模糊的“生成元”概念。
Skill 该谁能用
核心原则：
凡是“怎么研究问题”的方法，所有研究员共享；凡是“怎么治理整个 research program”的方法，Scientist 专属。

全员共享
包括 Scientist、Executor、Proposer、Challenger、Searcher 等都可以调用：
Research Skills
- measurement discipline
- assumption audit
- critical validation
- evidence independence
- discriminating experiment
- research expansion
- knowledge-gap search
- …
Discovery Skills
- representation shift
- assumption inversion
- analogy
- anomaly discovery
- reframing
- negative-space
- recombination
- …
Domain / Task Methods
只要内容本身是在讲“这种研究怎么做”，也应该共享，例如：
- program optimization
- physics analysis
- data analysis
- ML research
因为 Executor 也是第一等研究员，它也应该知道性能优化怎么做、怎么重新 framing、怎么发现新机制。
Scientist 专属
只有program-level governance 才需要 Scientist 专属，例如：
- mission-identify：整个任务属于哪种研究、总体采用什么研究范式
- team composition：现在整个实验室应该开什么席位
- program transition：什么时候全队换研究方向
- final synthesis / delivery
- 整个 program 的最终 allocation / adjudication
Scientist 的特殊性不是：
它掌握更多科研方法。

而是：
所有人都能研究和发现，但整个团队最后在哪里收敛、怎么分配火力、什么时候转折，由 Scientist 决断。

这正好符合之前定下来的：
信息平、持题共有、决断中心。

共享不等于所有人常驻看到全部 Skill
能力库共享，但不同席位可以有不同的默认显著性。
例如：
- Proposer 更容易看到 discovery / hypothesis-generation
- Challenger 更容易看到 wall attack / assumption audit / contradiction
- Executor 更容易看到 measurement / validation / representation shift
- Searcher 更容易看到 knowledge-gap / analogy
但只是推荐和 attention bias，不是权限限制。
Executor 想调用 question-reframing，完全应该可以。
Proposer 想调用 measurement-discipline，也可以。
一句话最终版：
Research Skills 教整个团队怎么做好科研，Discovery Skills 教整个团队怎么制造突破；这些能力属于所有研究员。Scientist 不垄断研究能力，只垄断整个 research program 的最终决断。
