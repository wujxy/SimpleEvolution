可以，我觉得现在可以把它压成一版非常干净的核心定义：

## Scientist + Claude Code Research Team

### 1. Scientist 是真正的研究负责人

Scientist 不是 proposer，也不是 executor，更不是一个“会调用科研工具的 agent”。

它承担整个课题的研究责任：

- 理解当前问题；
- 维护自己对问题的假设/认知模型；
- 判断现在最值得研究什么；
- 决定什么时候继续当前方向、什么时候换方向；
- 根据实验结果更新自己的判断；
- 整合不同助手的意见；
- 对最终研究进展负责。

它可以自己看代码、看数据、查关键细节、做小验证，但**默认不把主要精力耗在实现和重复实验上**。

核心原则是：

> **Scientist 负责判断，助手负责劳动。**

---

## 2. Claude Code 分化成 Scientist 的几个强力助手

底层都可以是很强的 Claude Code，只是承担不同职责。

### Searcher

负责：

- 查文献；
- 查相关方法；
- 查已有工作；
- 找事实和背景。

它的职责是把信息带回来。

**不替 Scientist 决定下一步研究什么。**

---

### Proposer

负责：

> 在 Scientist 当前给定的研究问题或研究区域里，提出值得尝试的方向。

例如 Scientist 判断：

> FCN 当前仍然是主要瓶颈。

它可以让 Proposer：

> 针对 FCN 提出几个真正有希望的结构性优化方向。

而当 FCN 被证明接近耗尽后，Scientist 应主动改变委托：

> FCN 方向已经充分探索。重新审视当前 world，寻找其它高价值方向。

因此 **Proposer 不负责决定什么时候转向**。

这是 Scientist 的职责。

---

### Executor

负责把研究想法真正做出来：

- 改代码；
- debug；
- train；
- simulation；
- profiling；
- benchmark；
- 做实验和对照；
- 返回真实结果。

它的目标是：

> **高质量、高效率地执行已经选定的研究意图。**

不要让 Executor 偷偷接管整个课题。

---

### Reviewer / Challenger

负责独立批判：

- 当前判断是不是站得住；
- Scientist 是否陷入路径依赖；
- 一个方向是否真的 exhausted；
- proposal 有没有明显漏洞；
- 实验结果有没有其它解释；
- 是否遗漏了重要方向。

它不是裁判，也不自动决定路线。

它负责：

> **攻击 Scientist 当前的认知。**

最终是否接受批评，仍由 Scientist 判断。

---

# 3. 整个系统真正的核心循环

不是固定：

\[
Searcher\rightarrow Proposer\rightarrow Executor\rightarrow Reviewer
\]

那会变流水线。

而是：

\[
\boxed{
Scientist\ Judgment
\rightarrow
Delegate
\rightarrow
Result
\rightarrow
Updated\ Scientist\ Judgment
}
\]

Scientist 根据当前处境自由决定叫谁。

比如：

> 不懂问题  
> → Searcher 查文献。

> 已经基本理解问题  
> → Proposer 提方向。

> 一个方向值得验证  
> → Executor 做实验。

> 连续几轮收益很差  
> → Reviewer 从外部批判。

> Reviewer 提醒可能有新方向  
> → Searcher / fresh Proposer 再调查。

所以真正持续存在的是 **Scientist**。

下面的 Claude Code 可以不断 fresh。

---

# 4. 最重要的是 Scientist 要维护“当前认知”，而不是维护过去路线

OMILREC 的失败模式非常典型：

\[
FCN
\rightarrow +15\%
\rightarrow FCN'
\rightarrow +3\%
\rightarrow FCN''
\rightarrow +0.5\%
\rightarrow \cdots
\]

因为过去成功过，所以越来越舍不得离开。

理想 Scientist 应该形成：

> FCN 原本是主要 hypothesis。  
> 已进行了多次高价值实验。  
> 收益持续递减。  
> 当前 evidence 表明这一方向基本耗尽。  
> 因此不再把 FCN 作为主要 research opportunity。

也就是：

\[
Hypothesis_t
\xrightarrow{Experiment\ Results}
Hypothesis_{t+1}
\]

**过去留下的是知识，而不是惯性。**

这一点可能是整个系统最重要的长期机制。

---

# 5. Proposer 最需要防止的就是“被 Scientist 的旧方向污染”

这里不是说 Scientist 不能指定方向。

如果 Scientist 有充分依据认为：

> FCN 值得深挖。

当然应该直接让 Proposer 研究 FCN。

真正的问题是：

> **当现实已经告诉 Scientist 这条方向基本耗尽时，它能不能自己承认这一点，然后改变给 Proposer 的问题。**

因此：

### 深挖阶段

> “FCN 仍然值得研究，针对它提出 proposal。”

### 转向阶段

> “FCN 已经基本耗尽。不要再围绕它优化，从当前 world 重新寻找其它机会。”

**谁决定从前者切到后者？Scientist。**

这就是 Scientist 的科研判断。

---

# 6. Fresh Claude 的另一个价值：降低路径依赖

Scientist 自己长期存在，因此天然可能形成偏见。

Fresh Claude instances 提供独立采样：

- 一个查文献；
- 一个重新审问题；
- 一个提出新方向；
- 一个实现；
- 一个专门反驳。

所以分工不仅是为了：

> parallelism。

更重要的是：

\[
\boxed{\text{global continuity}+\text{local fresh cognition}}
\]

Scientist 保留长期知识。

助手避免继承不必要的局部惯性。

这是很有价值的组合。

---

# 7. 但 Scientist 不能退化成项目经理

这是最大的反面风险。

不能变成：

> Searcher 给摘要 → Proposer 给方案 → Executor 给结果 → Reviewer 给评价 → Scientist 点确认。

那真正科研的是下属，Scientist 只是 dispatcher。

所以不可外包的核心仍然只有三件事：

> **What do I currently believe?**

> **What matters now?**

> **What should we do next?**

助手可以提供一切信息、方案和执行能力。

但这三个判断必须属于 Scientist。

---

## 最终可以压成一句话

> **Scientist 是持续存在的研究负责人，维护对课题的当前认识并负责研究方向的选择与更新；Claude Code 被分化为 Searcher、Proposer、Executor、Reviewer 等强力助手，各自承担具体认知或执行劳动。Scientist 可以亲自接触代码和现实，但避免长期陷入局部实现；实验和助手的反馈不断修改 Scientist 的判断，由 Scientist 决定继续、深入、转向或结束。**

更短一点就是：

\[
\boxed{
\textbf{One persistent Scientist}
+
\textbf{many strong, fresh Claude collaborators}
}
\]

**Scientist 掌舵，Claude Code 发疯干活。**

可以。这个设计不是因为“多 agent 看起来更像科研团队”，而是因为我们前面的实验和失败轨迹暴露了一个很具体的问题：

> **同一个 agent 如果既负责长期研究判断，又长期亲自做局部实现，很容易把“刚刚做过的事情”误当成“接下来最值得继续做的事情”。**

所以我们才把研究判断和具体劳动拆开。

最核心的原因有四个。

第一，**减少路径依赖**。像 OMILREC 里，agent 发现 FCN 有收益后，就会因为刚刚读过、改过、debug 过 FCN，继续围着 FCN 做微小优化。局部成功会不断强化同一路径。让 Executor 去做具体实现后，Scientist 收到的是“结果”，而不是整个实现过程，更容易重新判断这条方向还值不值得继续。

第二，**保留全局注意力**。Scientist 最稀缺的能力不是写代码，而是判断“现在最重要的问题是什么”。如果它大量时间都花在编译错误、接口修改、训练脚本、参数 sweep 上，它的上下文和注意力都会被局部细节占满。Searcher、Executor、Proposer 分担的是劳动，让 Scientist 保留对整个课题的视野。

第三，**引入 fresh cognition**。Scientist 是长期存在的，所以一定会形成自己的偏见。Fresh Proposer、Reviewer、Searcher 的价值不只是并行，而是它们没有继承 Scientist 全部的局部惯性。Scientist 可以让一个 Proposer 深挖当前方向，也可以在方向耗尽后让另一个 fresh Proposer 重新看世界，从而获得真正独立的第二视角。

第四，**让不同工作各自优化注意力**。查文献、提方案、写代码、批判路线，本来就是不同类型的工作。Searcher 可以专注找事实，Executor 可以专注把实验做对，Reviewer 可以专门攻击当前判断。没必要要求一个长上下文里的单 agent 同时在“发散、执行、批判、收敛”之间始终切换得完美。

但这里最重要的不是分工本身，而是**权力边界**：

> 劳动可以委托，科研判断不能委托。

Searcher 可以告诉 Scientist 文献里有什么；Proposer 可以提出方案；Executor 可以返回实验结果；Reviewer 可以说当前路线可能错了。

但最终仍然是 Scientist 自己判断：

> 我现在相信什么？  
> 哪个方向还值得投入？  
> 这个 hypothesis 是否已经耗尽？  
> 下一步该继续、转向还是停？

所以这套设计真正想实现的是：

\[
\boxed{
\text{长期连续的研究判断}
+
\text{局部 fresh 的强执行能力}
}
\]

而不是简单的 multi-agent。

一句话概括就是：

> **我们希望 Scientist 像一个真正负责课题的研究者：自己掌握问题和方向，把大量具体劳动交给强力助手；助手帮它扩大能力和视角，但不能替它形成最终科研判断。**

最终它有没有价值，还是要靠 JUNO benchmark 打脸：如果这种分工不能在固定预算下比一个 Claude 自己从头干到尾做得更快、更好，那就说明这套设计没有必要。
