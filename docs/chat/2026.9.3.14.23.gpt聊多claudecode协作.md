可以，下面这版我会直接发给执行 agent。核心不是再扩设计，而是把刚才讨论后的**收缩方向和最终裁决**讲清楚。

我看完《演化实验室设计》以及后续讨论后，整体主干认可，但有一个重要收缩：**不要再把认知变异做成一套独立的 machinery。系统应该尽量接近 Anthropic AAR 的形状——多个长期 autonomous researchers 并行生活、横向交流、共享研究记录；卡住时首先通过 peer interaction 获得新视角，而不是经过额外的 proposer/challenger/genealogist 流程。**

当前基线我建议收束成下面这样。

---

## 1. Node 保留，但重新明确它的意义

Node 仍然有意义，但它不再是 agent 的组织结构，也不负责制造变异。

Node 只表示：

> **经过 authoritative evaluator 确认的 immutable world checkpoint。**

即文档现在的：

`git SHA + objective + gates + parent`

这个定义保留。多个 researcher 可以从同一个 Node 出发，各自拥有独立 workspace；一个 researcher 也可以随着自己产生的新 world 持续跨 Node 研究，不需要 Node 晋升一次就重新启动 researcher。文档目前“Node 本身冻结、researcher 各自 fork、incorporates 记录横向吸收”的设计是对的。

因此新的语义是：

- Population 产生 variation；
- evaluator 做 selection；
- Node tree 记录 validated world inheritance / provenance。

Tree 仍然存在，但它是**世界谱系**，不是 agent workflow。

---

## 2. Researcher 第一版就是长期 Claude Code

这点继续保持文档当前设计：

> Claude Code 负责科研；SimpleEvolution 提供实验室。

每个 researcher 是完整长期 autonomous trajectory，自行读代码、profile、假设、实现、实验、改变方向、吸收别人代码。不要重新实现 ReAct，也不要恢复 Executor/Proposer/Challenger/Reviewer 的流水线。

关键修正是：

> **不要把 researcher 当一代一代的 disposable worker。**

过去 `Executor A → 250ms → fresh Executor B 接力` 效果不好，一个重要原因是：

- A 的深层 code/world cognition 丢了；
- B 却继承了 A 的 framing；
- B 又重新支付读代码和实验 warm-up 成本。

所以默认应该是 researcher 持续活着、持续研究。

Fresh researcher 是昂贵的 diversity 手段，不是标准接力方式。

---

## 3. 认知变异首先来自 researcher 之间直接交流

这里是这轮最大的收缩。

不再设计：

`plateau → genealogist → proposer mirror → challenger mirror → bet/dissent → seed → 新 researcher`

这种认知子系统。

多个长期 researcher 本身就已经是不同的脑，而且都已经支付了理解代码和实验环境的成本。

因此 A 卡住时，最自然的是：

> A 直接找 B/C 讨论当前 framing。

例如：

“A：我现在做到 250ms，我怀疑剩下的是 Minuit call-count floor。你从你的路线看，有没有反例或者完全不同的解释？”

B/C 可以根据各自真实 trajectory 给 A：

- 不同 evidence；
- 反例；
- 新 framing；
- 可复用代码；
- 一个没被 A 看见的新方向。

A 自己决定是否接受，然后继续自己的原 session。

不需要 judge，也不需要正式 debate protocol。

**Peer conversation 本身就是最便宜的 cognitive mutation。**

只有整个 population 都明显陷入同一个 worldview 时，才考虑额外 fresh perspective；这是低频逃生机制，不是主循环。

---

## 4. Collaboration 只保留两条通道

### 异步：Shared Research Record

继续保留 findings。

公共层放：

- 做过什么；
- 结果怎样；
- evidence；
- commit/world；
- 可复用发现。

文档里“事实共享，认知不同步”的核心原则保留；更准确地说，是：

> **共享可再裁判、带 provenance 的研究对象，不共享一个统一 worldview。**

文档当前 finding 的署名、实验、commit 结构是合适的。

### 同步：researcher-to-researcher message

研究员需要：

- 问同行；
- debate；
- challenge；
- 通知 breakthrough；
- 讨论 merge；
- 请求不同视角。

这个 communication 不经过 Supervisor。

我们刚确认 Claude Code 已有 cross-session messaging，并且长期 `claude -p` session 可以作为独立 session 通信，因此 **v1 没必要为了 peer communication 切 Agent SDK，更没必要自己实现 message bus/ReAct loop。**

第一版应优先使用 Claude Code 自己的 session communication。

---

## 5. Shared findings 和 peer message 不要混

两者用途不同：

- **message = 临时对话**
- **finding = 实验室公共记录**

重要结果最终应该 publication 到 shared record，而不是只存在 A→B 私聊里。

反过来也不要要求 researcher 每一步都同步 findings，否则会破坏独立 trajectory，并增加 context 污染。

Lab Protocol 保持极短即可：

1. 有对同行有价值的结果 → publish finding；
2. 准备进入明显新方向 → 看近期 findings；
3. 卡住或需要另一视角 → 找 peer 交流；
4. 吸收别人代码后的 candidate → 重新过 evaluator。

这已经足够。

---

## 6. §7 的谱系学家/三层变异体系建议退出 v1

目前文档 §7 的：

- 谱系学家；
- proposer 镜；
- challenger 镜；
- seed'/bet/dissent；
- informed quota；
- saturation trigger；

我建议全部从 **v1 baseline** 后移成 future candidate。

不是说这些想法错，而是目前没有证据证明 population 需要这么多机制，而且它们重新出现了“harness 帮 researcher 科研”的风险。

v1 的 diversity 来源先只保留：

- 多个长期独立 researcher；
- 不同初始 broad seed（如果需要）；
- shared findings；
- peer conversation；
- 偶尔 fresh researcher。

先看真实 population 是否会自己产生 mutation。

如果以后实测：

> peer communication + findings 仍然无法走出 collective floor，

再给 genealogist / fresh mutator 一个真实问题作为存在理由。

---

## 7. Supervisor 继续做得很“蠢”

文档当前这一点非常重要：

> Supervisor 管“哪里值得放 researcher”，不管“进去以后怎么研究”。

继续坚持。

Supervisor v1 不应该：

- 判断应该 challenge 哪个 assumption；
- 决定该生成什么 hypothesis；
- 触发复杂认知流程；
- 总结 worldview 再广播。

它只看：

- validated nodes；
- objective/gates；
- active researchers；
- evaluator queue；
- budget/slots。

负责 population / resource / world allocation。

“聪明的变异，愚蠢的选择”仍然是很好的总原则。

---

## 8. 最终 v1 可以压缩成这个结构

```text
                    SimpleEvolution
              world / process / eval / slots
                         │
         ┌───────────────┼───────────────┐
         ↓               ↓               ↓
      Claude A         Claude B        Claude C
      workspace A      workspace B     workspace C
      long-lived       long-lived      long-lived
         ↕               ↕               ↕
         └──── peer communication ────────┘
                         │
                  Shared Findings
                         │
                Authoritative Evaluator
                         │
                 Validated World Nodes
```

这就是第一版。

不要再继续加：

- 固定 cognitive roles；
- formal debate；
- plateau cognition state machine；
- genealogist；
- multi-level seed ontology；
- LLM Supervisor。

先把几个长期 Claude Code 真正放进一个实验室，让它们：

> 并行研究、自己交流、自己借代码、自己换视角、自己持续推进。

如果这一版仍然形成 collective false floor，我们再从真实 failure 往上加机制。

---

一句话收束：

> **旧 SimpleEvolution 的核心对象是 proposal；旧 Scientist 的核心对象是中心脑判断；新的核心对象应该是 long-lived autonomous research trajectory。Node 只记录世界，Shared Record 保存公共科研事实，Claude Code 之间直接协作，Supervisor 只管理 population。**

我建议据此把当前设计文档再瘦一次，特别是把 §7 从基线里拿出去，其余 world / researcher / shared record / evaluator / node lineage 主干基本可以冻结。

这一版我觉得已经把我们的最新共识压得很干净了：**不再试图设计“聪明的多智能体科研流程”，而是先把几个真正独立、长期活着、能够互相交流的强 researcher 放在一起。**
