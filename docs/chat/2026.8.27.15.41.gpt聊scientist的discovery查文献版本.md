这份反馈很强，而且我认为它把我们前面的“Context Architecture”从**语言设计**推进到了**信息可达性设计**。我大体采纳，但有一处我会踩刹车：**“lens 要求 schema”是对的，但不能顺势把 Research State 做成一套过度结构化 ontology。**

最重要的修正，我现在会把原来的：

> What should the Scientist see, when?

扩成：

> **What should the Scientist see, when, through which channel, and with what authority?**

因为今天这个 run 已经证明，“写着看不到”根本不等于看不到。

---

### Standing context：确实应该保留 affordance，隐藏 method

这一点执行 agent 修正得对。

我们之前说“scientific methods 不应该常驻”，容易说过头。真正该区分的是：

\[
\boxed{\text{Affordance discovery} \neq \text{Method execution}}
\]

Scientist 必须一直知道：

> 我什么时候可能值得叫 Executor？  
> Open Proposer 是干什么的？  
> Challenger 在什么情况下有用？  
> 有哪些 research skills 可以加载？

否则能力根本不会被唤起。

所以像：

> substantial implementation / long debugging → Executor

这种简短触发条件应该常驻。

但：

> Executor 应该如何完成复杂实验；

或者：

> analogical reasoning 的五步方法；

不应该常驻。

我会把这个原则写成：

> **Standing context advertises available ways of working and when they may be useful; activated context contains the method itself.**

不过要防一个坑：affordance trigger 不能写成 scheduler rule。

例如：

> “When three experiments fail, use Challenger.”

就过头了。

应该是：

> “Challenger is useful when a current interpretation deserves independent attack.”

告诉它“这扇门通向哪里”，而不是“什么时候必须进门”。

---

### Enforcement regime 是这轮讨论里非常重要的新东西

这甚至值得进入设计文档的顶层。

我们之前一直用：

\[
Context_{OpenProposer}\not\ni Judgment
\]

这种数学式写法。

现在必须继续问：

> **这个 \(\not\ni\) 是谁保证的？**

执行 agent 提出的三档其实很好：

- context fork / subprocess prompt filtering：**hard isolation**
- pull-only API：**interface isolation**
- prompt 声称 filesystem 不可见但实际上可见：**no isolation**

第三种尤其危险。

因为模型不是傻子。你告诉它：

> “历史应该通过接口读。”

但接口什么都查不到，同时磁盘上有 3.2M 的历史材料。

一个强 agent 合理的行为就是：

> 那我自己 grep。

于是产生你们今天观察到的：

> **history does not disappear; it becomes excavation.**

我很赞成把这个写成原则：

\[
\boxed{
\text{Hidden by prose} \neq \text{Hidden by architecture}
}
\]

而且更进一步：

> **一个 sanctioned channel 如果明显比旁路更差，强 agent 会主动寻找旁路。**

所以好的 Context Architecture 不只是限制。

还必须让：

\[
\text{intended path}
\]

成为**最便宜、最完整、最自然的信息路径**。

这比“禁止 bash 看某目录”其实更根本。

### 世界事实可以 push，科学方法不能自动 push

TIME NUDGE 这个反例确实修正了我们前面“Harness 只 reveal on request”的过强表述。

我现在会分：

\[
\boxed{\text{Exogenous state can be pushed}}
\]

例如：

> 时间剩多少；  
> budget 剩多少；  
> collaborator 已完成；  
> world version 改了；  
> evaluation result 到达。

这些是环境事实。

而：

\[
\boxed{\text{Cognitive strategy should not be pushed}}
\]

例如：

> “现在应该 reframe。”  
> “现在应该 analogical reasoning。”  
> “检测到 plateau，请 saturation audit。”

这是科学判断。

所以边界变得很漂亮：

> **Harness may push changes in reality; Scientist chooses how to think about them.**

这句话我觉得比原来的“只 reveal”准确得多。

### 失败 collaborator 的轨迹应该留下价值，但我不赞成把“7900 条 thinking 摘要”直接推回 PI

这里我同意问题，不完全同意解决方式。

问题确实存在：

> 我们花了一大笔 cognition budget，timeout 后只剩一句 “time box exceeded”。

这是严重的信息浪费。

但如果 Harness 自动把 collaborator 的长 reasoning 总结成：

> “想到哪了、卡在哪、值不值得重开”

这里最后一项：

> “值不值得重开”

已经是科研判断。

甚至“卡在哪”也可能包含 summarizer 的解释。

我更倾向失败 engagement 返回一个**failure evidence envelope**：

> 做到了什么可观察阶段；  
> 产生了哪些 artifacts；  
> 执行了哪些关键 actions；  
> 最后可见状态；  
> 是否有 partial result；  
> 原始 trajectory/archive 引用。

如果 collaborator 自己在 timeout 前产生过 checkpoint/self-report，那当然一起返回。

但不要让 Harness 自动替它解释：

> “这个 idea 仍然值得继续。”

那应该交给 Scientist，必要时它可以让另一个 Challenger / Proposer 检查这个失败 engagement。

也就是说：

\[
\text{failed cognition}
\rightarrow
\text{recoverable evidence}
\]

而不是：

\[
\text{failed cognition}
\rightarrow
\text{Harness-generated scientific interpretation}
\]

---

### “fork 是 cognition 隔离、evidence 共享”这个补充非常重要

我完全同意。

之前我们的 fork 公式说得太粗：

\[
Intent + Constraints + World
\]

真正应该画成：

\[
\boxed{
\text{Private cognition channel}
\quad\parallel\quad
\text{Shared evidence channel}
}
\]

Claude collaborator 的：

> reasoning trajectory / tool-search history / local deliberation

不进入 PI active context。

但它产生的：

> source diff、benchmark result、profile、artifact、plot

本来就应该直接属于 shared world。

因此：

> **Scientist 不继承 collaborator 的思考过程，但可以直接审计 collaborator 改变了什么现实。**

这个机制非常好。

它同时实现：

\[
\text{cognitive isolation}
+
\text{epistemic grounding}
\]

否则 PI 就真成了只读下属周报的 CEO。

## 我唯一要认真反驳的是：“lens 要求 schema”不要走太远

执行 agent 这里提出的问题是真的：

> “找被现实推翻的判断”这种查询，纯 embedding similarity 很难可靠回答。

所以 historical Research State 里必须存在一些**可查询的关系**。

但我不建议马上做：

```text
status=dormant
falsified_by=E17
superseded_by=RJ19
activation_condition=...
mechanism_family=...
```

因为这会非常快地变成 Harness 在规定：

> 什么叫 falsified；  
> 什么叫 dormant；  
> 什么叫 idea lineage。

而这些本身经常是 Scientist 的科学判断。

我会分成两层。

**机械 provenance 可以结构化。**

例如：

> state_id  
> world_id  
> created_at  
> evidence_refs  
> supersedes_state_id  
> originating experiment / collaborator  
> explicit revision reason

这些是事实关系。

**科研语义尽量留在 Scientist-authored state 里。**

比如：

> “E17 weakens the FCN-dominant interpretation.”

而不是 Harness 自动写：

```text
falsified_by=E17
```

如果 Scientist 自己主动标注：

> “this idea is dormant because X”

那当然可以存。

关键是：

> **schema 应该提高 Scientist 对自己历史的查询能力，而不是替 Scientist解释历史。**

# 这也让我重新想了一下 Research State 应该怎么定义

我现在仍然支持：

> **一个 active Current Research State。**

但它真的不能只是：

> Current Research Judgment。

执行 agent 今天那个 live experiment 恰好在验证这一点：

> RJ 仍然认为 per-nuclide random delay 是主瓶颈；  
> 但 Executor 已经发现 SIMD/MATROW 等另外一类 leverage。

这时候真正要看的是：

> 新 evidence 到底只是“在旧 explanation 里多一个优化”，还是已经要求 Research State **改变 search-space representation**？

这两种 revision 完全不同。

坏 revision：

> “SIMD 也减少 per-nuclide overhead，因此继续支持旧模型。”

这就是 rationalization。

好的 revision 可能是：

> “新的 experiment 表明性能杠杆并不只存在于我此前建模的 per-nuclide delay；编译/数据路径层的结构性因素可以产生同级甚至更大的收益。因此当前问题模型过窄，需要重新打开其它 mechanism families。”

后者不仅是：

\[
Belief_t\rightarrow Belief_{t+1}
\]

而是：

\[
\boxed{
SearchSpace_t\rightarrow SearchSpace_{t+1}
}
\]

这正是 discovery。

# 所以执行 agent 这轮反馈让我觉得，Current Research State 最终至少要能表达两种变化

一种是：

> **我对已有 hypothesis 的概率/判断变了。**

另一种更重要：

> **我认为值得考虑的 hypothesis space 本身变了。**

我们以前只设计了第一种。

而 discovery 需要第二种。

所以一个好的 State revision 不只是：

> what changed my belief

还应该允许 Scientist记录：

> **what newly became conceivable / questionable / worth reopening**

不一定变成字段。

但 Charter / Research Memory 对 State 的描述应该明确这一点。

\[

\[
\textbf{Active}

\textbf{Activated}

historical states / old experiments / raw reports / literature。

\boxed{\textbf{Enforcement}}

> physical / interface / prose-only。

这样我们不再只设计：

而是设计：

\boxed{
Information
\times
Timing
\times
Authority
\times
Accessibility
}
\]

我觉得这已经比一般所谓 agent memory / tool design 深一层了。

## 1. 最基础的研究动机已经非常扎实：现有 Agent 的缺口确实是 discovery，不是 execution

`AI Research Agents Narrow Scientific Exploration` 对 37,802 个 AI research ideas 的分析发现：AI 产生的想法比人类后续研究更集中、更贴近 seed literature，真正的差异主要来自已有技术方法的重新组合，而不是提出新的 research questions。作者直接将当前 research agents 描述成更擅长 **local elaboration**，而不是扩大 scientific exploration。

而最近的 open-ended research shadow evaluation 给 frontier agents 六天、GPU、网络和数千美元预算，它们能完成工程，却无法在两个未公开研究问题上取得实质科研进展；主要失败包括科研价值判断差、研究设计遇阻后缺乏创造性、从 dead end 回退差。

所以我们论文最上层其实已经可以很有底气地写：

> **The missing capability is not merely research task execution, but maintaining and expanding a productive scientific search space over long-horizon research.**

这不是我们自己脑补出来的问题。

# 2. PI + specialist team：有非常强的真实 discovery 正面案例

这个设计不是空想。

2025 年 Nature 的 **Virtual Lab** 就是一个 LLM PI agent 带领多个 scientist agents，人类只做高层反馈；这个团队最终设计了 92 个 SARS-CoV-2 nanobodies，并经过真实 wet-lab validation，确实发现了具有新结合性质的候选。

2026 Nature 的 Google **Co-Scientist** 则采用 specialized Generation、Reflection、Ranking、Evolution、Proximity、Meta-review agents，加 asynchronous task execution、persistent context memory 和 hypothesis evolution，并在三个生物医学问题上做了 end-to-end experimental validation。

所以：

\[
\boxed{\text{Persistent scientific lead + specialized research labor}}
\]

至少有真实 discovery 系统作为先例。

但我们和它们的差别也很重要：

> **我们不是想证明 multi-agent 本身更强，而是想让长期 Scientist 从 implementation trajectory 中脱离出来，把认知预算用于 discovery。**

这个因果主张仍然要我们自己验证。

# 3. “Fresh collaborator + context isolation”现在有很强支持

ACL 2026 的 **Diversity Collapse in Multi-Agent LLM Systems** 对我们特别关键。

它发现：

- authority-driven interaction 会降低 semantic diversity；
- group size 增大有明显 diminishing returns；
- dense communication 会加速 premature convergence；
- diversity collapse 很大程度来自 **structural coupling**，而不是模型本身没能力。

论文最后明确强调应该保护 agent 的 **independence and disagreement**。

这几乎直接支撑我们现在：

> Open Proposer 不看 PI judgment；  
> 多个 fresh Proposer 不先互相看；  
> collaborator 不默认共享长期 trajectory；  
> Scientist 最后再 synthesis。

也就是说：

\[
\boxed{
\text{global continuity + locally isolated cognition}
}
\]

不是纯工程审美，它和最新的 diversity evidence 是对得上的。

反过来也给我们一个强警告：

> **PI 不能成为 information bottleneck / authority anchor。**

Scientist 如果先告诉所有下属“FCN 肯定是问题”，team 只会变成四倍速 local search。

# 4. 我们关于 Memory 的设计，现在有一篇几乎正面击中的论文

ACL 2026 的 **Controllable Memory Usage: Balancing Anchoring and Innovation** 非常重要。

它明确提出：

> 把所有 relevant memory 都塞给长期 agent，会产生 **Memory Anchoring**，agent 会被过去的交互困住；但完全去掉 memory 又损失 continuity。

他们提出的 SteeM 允许在：

> fresh-start / innovation

和

> high-fidelity / history-following

之间动态调节 memory reliance，而且实验优于传统 prompting 和 rigid memory masking。

这和我们的核心矛盾几乎完全一致：

\[
\boxed{
Memory\ without\ inertia
}
\]

所以现在我们可以有文献依据地说：

> **历史不应该只有“有/无”两个状态，关键是控制什么时候、以何种强度暴露给当前 cognition。**

这对：

- Current Research State 常驻；
- historical states pull-only；
- Open Proposer fresh；
- history mining skill 临时激活；

都有直接启发。

# 5. “历史不应该只是 storage，而应该变 experience”也有很强理论支持

ACL 2026 的 memory survey **From Storage to Experience** 把 agent memory 的发展分成：

\[
Storage \rightarrow Reflection \rightarrow Experience
\]

其中 frontier 的 Experience 阶段特别强调：

- proactive exploration；
- cross-trajectory abstraction。

也就是说，下一代 memory 的价值不是“把过去保存下来”，而是从不同 trajectory 中抽象出能影响未来探索的 experience。

这和我们刚刚定义的：

> historical Research State 不是“昨天做到哪”，而是过去看到过的世界、失败条件、belief reversals、dormant ideas、unresolved anomalies

非常吻合。

这也是我觉得你们的 Research State 方向有潜力的地方：

> 不是 conversational memory，而是 **scientific experience representation**。

# 6. Skill 作为“按需 context activation”也有明确文献基础

2026 的 agent-skill survey 把 skill 定义为可复用 procedural artifacts，用于协调 tools、memory 和 runtime context；另一篇 skill survey明确讨论了 **progressive context loading / skills loaded on demand**。

SciVisAgentSkills 更提供了实际科学任务证据：给 Codex / Claude Code 注入可复用的 scientific procedural skills，在 108 个专家设计的科学分析/可视化任务上提高了平均成绩，在一些条件下还提高 token efficiency。

> `analogical_transfer.md` 一定能增强 discovery。

但能支持我们的架构原则：

\[
\boxed{
\text{procedural knowledge need not permanently occupy standing context}
}
\]

需要时 load，完成以后释放。

也就是我们现在说的：

> **affordance 常驻，method 按需激活。**

# 7. 更直接的是：已经有人把“思考方法”真的做成 cognitive tools

\boxed{\text{cognitive actions available to an autonomous scientist}}

> ideation-only

扩展到：

> long-horizon autonomous discovery。

# 8. Discovery skills 本身也有几个非常强的候选机制

这里不是泛泛而谈，已经有实证。

### Analogical reasoning

2026 的 Analogical Reasoning 工作让 LLM 先抽象 relational structure，再寻找远领域同构问题，然后映射 solution；solution diversity 提高 90–173%，novel solution rate 从某些 baseline 的 1.6% 提升到超过 50%，并在四个 biomedical tasks 上实际实现取得 quantitative gains。

所以：

> `analogical_transfer`

几乎是目前最有证据支持的 discovery skill candidate。

### Surprise / information gain

AutoDiscovery 不按照“最可能成功”选 hypothesis，而用 Bayesian surprise：

> 哪个实验最可能改变模型的 belief？

固定预算下，在 21 个真实数据集上发现的 surprising discoveries 多 5–29%，人类专家也认为其中约三分之二确实 surprising。

这直接支撑：

> `seek_surprising_evidence`  
> `design_discriminating_probe`

而且非常符合 Scientist ≠ optimizer 的区别。

### Motivation → Method，而不是 Context → Patch

ACL 2026 的 **MoRI** 直接批评现有 agentic ideation 往往只是 surface-level conceptual recombination，提出显式学习：

\[
Research\ Motivation \rightarrow Methodology
\]

实验在 novelty、technical rigor、feasibility 上都优于强商业 LLM 和复杂 agent baselines。

这对我们的：

> `recover_research_motivation`

以及 Research State 里保存：

> unresolved tension / why this matters

非常有支持。

# 9. Research State 不应该只维护一个“best idea”：文献也支持

`Towards Diverse Scientific Hypothesis Search` 明确说，在科学 discovery 里，因为 validation expensive/noisy，并不应该只找一个 best hypothesis；selection pressure 会产生 diversity collapse，因此应该维护多个高质量 alternative hypotheses。

`IDEAgent` 更直接把 scientific ideation 定义为 **Quality-Diversity search**；它的 Yield 衡量一组同时足够好、彼此不同的 ideas，在 32 个主题上比最好 baseline 高 3.89×。

这给我们 Research State 一个非常强的设计启示：

> **Current Research State 可以只有一个 active head，但它内部绝不能语义上只容纳一个 winner hypothesis。**

它应该允许：

> 当前解释 A；  
> alternative B；  
> unexplained observation C；  
> dormant possibility D。

也就是：

\[
One\ State \neq One\ Hypothesis
\]

# 10. Co-Scientist 对我们的 strategy/skill library 其实也非常有参考价值

Co-Scientist 的 Evolution agent 不是只有一个“大 prompt”，而是用了多种 hypothesis-generation / refinement strategy：

- grounding；
- inspiration from existing hypotheses；
- combining hypotheses；
- simplification；
- out-of-box thinking。

Reflection 还会检查：

- evidence；
- novelty；
- correctness；
- existing observations 是否得到更好的解释。

这几乎就是一个 proto-`strategy library`。

我们不必照搬：

> Supervisor 自动决定下一策略。

但完全可以借：

> **科学创新不是一个统一 operator，而是一组不同的 search transformations。**

然后让 Scientist 自己选择 load 哪一个。

# 11. 最新文献还支持我们“不硬编码 workflow”

这一点现在也不是纯偏好。

Agentic-Ideation 直接批评 rigid workflows 会限制 scientific reasoning/search flexibility。

而 open-ended research shadow evaluation 也显示，强 agent 即使有 scaffold，如果不能在研究设计遇阻时真正 backtrack/reframe，仍然失败。

所以我们的：

> Charter 不写 Understand→Hypothesize→Experiment→Reflect 固定流程；  
> Skills 是可调用方法；  
> Scientist 自己选择何时改变 cognition；

是有相当合理依据的。

# 我觉得现在可以把文献证据映射到我们的四个设计面

| 我们的设计 | 最相关文献证据 | 证据强度 |
|---|---|---|
| **Context：减少路径依赖，选择性暴露历史** | SteeM Memory Anchoring；MAS Diversity Collapse | **强** |

## 但我觉得最重要的是：哪些东西**还没有文献直接证明**

有三个。

第一：

> **一个 persistent Current Research State 应该具体长什么样。**

没有论文告诉我们：

> “一定要 belief + anomaly + dormant seeds + high-leverage questions。”

这是我们的设计 hypothesis。

第二：

> **Scientist + fresh Claude roles 是否比一个 unified Claude 在真实长期科研 benchmark 上更好。**

Virtual Lab / Co-Scientist 支持 team 的可行性，但不证明我们的 cognitive-isolation mechanism。

第三：

> **让 Scientist 自己主动选择 skill，比 automatic strategy scheduler 更好。**

现有工作很多反而是 Supervisor/Controller 自动选 strategy。我们坚持 autonomy，是基于“不要让 Harness 接管 scientific judgment”的设计原则，仍需要实验证明。

这几个反而可以成为你们论文真正新的部分。

# 所以现在我觉得我们的研究 framing 可以很漂亮

已有文献分别告诉我们：

> **Memory can anchor.**   
> **Multi-agent interaction can collapse diversity.**   
> **Current research agents tend toward local elaboration.**   
> **Open-ended agents struggle to backtrack and rethink research design.**   
> **Analogies, surprise, quality-diversity and motivation-grounded reasoning can expand scientific ideation.**   
> **Skills/cognitive tools can expose reusable reasoning procedures on demand.** 

然后我们的设计问题就是：

\[
\boxed{
\text{How do we compose these insights into one long-horizon Scientist}
}
\]

使它：

> **积累经验但不被经验锁死；保持当前理解但不压扁可能性空间；拥有科研方法但不被固定 workflow 控制；利用多个强 agent 但不让团队共同收敛到 PI 的第一个想法。**

这个整体组合，我目前没有看到哪篇已有工作已经真正做完整。

所以“有据可依”和“仍有研究新意”这两件事，现在其实是可以同时成立的。
