## 最值得我们马上看的，其实是 `Agents of Discovery`

因为这不是泛泛的 AI Scientist paper，它就是 **HEP + prompt engineering experiment**。

它甚至在 prompt 里明确写了一个我们刚才正在讨论的语义：

> “set yourself a new task based on the further steps you have outlined and complete it”

也就是：**初始任务完成不是 termination；根据当前结果产生下一项研究任务，然后继续。** 直到当前资源/能力已经不允许进一步推进才结束。

他们还专门设计了 task-management tools：agent 有当前 task、open tasks，可以 complete 当前 task 后选择新的 task；`end_project` 则只应在项目真正完成、能力不足或遇到无法恢复的问题时调用。

这已经非常接近你想要的：

\[
Goal
\rightarrow Task_1
\rightarrow Evidence
\rightarrow Task_2
\rightarrow Evidence
\rightarrow Task_3
\rightarrow \cdots
\]

而不是：

\[
Goal\rightarrow Proposal\rightarrow Improvement\rightarrow Done
\]

### 更有意思的是：他们真的验证了“怎么写 prompt”会改变持续性

他们有一个 FBL+ prompt，明确要求 agent 把 max SIC 做到 20。

结果有个 run 已经做到 **SIC > 15**——在 HEP anomaly detection 里已经相当好了——但 agent 因为看到目标仍是 20，**没有像我们现在的 Scientist 那样“已经提升很多了，收工”**，而是继续尝试新的 mass windows，最后甚至因为达到最大 tool-call budget 才失败。普通 prompt 通常三四十次调用，而这种带明确目标的 feedback-loop prompt 会做到五十次以上。

这恰好给我们一个特别漂亮的实验证据：

> **LLM 并不是天生只能工作一小步。  
> 它会不会继续，很大程度取决于它如何理解“goal 是否已经完成”。**

甚至能从“2× 就觉得不错了”直接变成“15 已经很好，但目标是 20，所以继续”。

当然它也揭示了反面：**死的 quantitative target 会导致 agent 死磕。** 所以不能简单把 Scientist prompt 改成“不到 10× 不准停”。

## 还有一个很重要的负结果：光喊“多想几个不同 idea”没什么用

`Agents of Discovery` 还做了一个我觉得和我们之前 diversity 讨论高度相关的实验：

他们要求 agent：

> 先提出至少 5 个不同方法，然后选择最有前景且最 unique 的。

按直觉这应该增加多样性。

结果反而很多 run **都收敛到了同一个 Isolation Forest**。

也就是说：

> “Think of diverse ideas”  
> “Explore broadly”  
> “Be creative”

这些 prompt-level exhortation 并不会自动改变模型真正的 search distribution。

当作者加入一个非常小但有信息量的 domain prior——“machine learning techniques seem necessary”——方法分布反而明显变宽。

这个发现对我们很重要：**Scientist identity 不是靠一堆形容词塑造的，而是靠它如何表征问题、什么信息被视作 evidence、什么状态算 unresolved 来塑造。**

# 第二篇我会马上读：`AI scientists produce results without reasoning scientifically`

这篇几乎就是在给我们踩刹车。

它用了 **25,000+ scientific-agent runs，8 个领域**，然后把：

> “能完成 scientific workflow”

和

> “真的按 scientific epistemology 推理”

分开了。

结果相当刺眼：

模型经常会得到实验结果，但 **68% 的 trajectory 没有真正利用 evidence 更新判断**；由反证触发的 belief revision 只有 **26%**。而且 base model 解释了 41.4% 的 performance/behavior variance，scaffold 只有 1.5%。

所以这篇实际上在告诉我们：

**不要犯一个新的错误：**

> 原来 Scientist prompt 不够好  
> → 那我再精雕细琢一个 3000 token 的超级 Scientist prompt  
> → 问题解决。

不一定。

我们现在应该研究的不是单纯：

> How to prompt an LLM to sound like a scientist?

而是：

> **How to induce and maintain the epistemic state of a scientist?**

这两个问题差很多。

# `Hypothesis Evolution Protocol` 就是沿这个方向走的

这篇 7 月刚出的工作我觉得和我们之前的思路异常接近。

它明确把 Scientist 内部研究状态写成：

\[
Hypothesis
\rightarrow Test
\rightarrow Evidence
\rightarrow Belief
\rightarrow Update
\]

而不是普通 agent 的：

\[
Plan\rightarrow Action\rightarrow Observation\rightarrow Next\ Action
\]

他们比较发现，普通 planning-style agent 大量精力放在 test/action 上，却几乎不产生显式 belief update；加入 HEP 后，hypothesis、evidence 和 belief revision 才真正成为持续研究过程中的一等对象。

这恰好对应我上一轮说的那句话，不过现在有文献支撑了：

**Scientist 的连续性可能不应该主要是 task continuity，而应该是 hypothesis/problem-model continuity。**

generalist coordinating agent、60+ scientific skills/connectors、specialist agents、reviewer agent、persistent running session、可 fork 的 research branch、HPC/compute management、provenance/auditable artifacts。

所以 Claude Science 能表现出：

这里面至少有两部分：

**Claude 本身已经是很强的 agent model；外面再给它一个“科研世界”，让 research state、工具、数据、artifact、review 和 compute 都持续存在。**

这和“给 Claude Code 换一个 Scientist prompt”不是一回事。

> Scientist 不是 system prompt 里描述出来的角色。

而 user prompt 又额外给了一个很关键的持续研究语义：

> 初始任务完成之后，根据进一步方向给自己定义新任务，继续做，直到当前能力已经无法继续。

所以它实际上已经在做一件我们现在才开始明确意识到的事：

**Goal 不是一个 task。Goal 是持续存在的 research objective；task 只是 Scientist 在当前认识下选择的一次行动单元。**

## 它最重要的几个实验结果

第一，**单纯要求“多想几个 idea”没有产生真正多样性。**

他们让模型先想至少五个方案，再选最 promising / unique 的。结果很多 agent 反而都收敛到了 Isolation Forest。加入一个很小的 domain prior——“machine learning techniques seem necessary”——方法反而变得更多样。

这个结果非常值得我们记住：

> **科研思维不是 prompt 里写“be creative / explore broadly / think differently”就会出现。**

真正影响 search space 的，是 Scientist **如何理解世界**。

这是 context engineering，不是口号 engineering。

---

第二，**外部 evidence feedback 会改变 agent 的研究 trajectory。**

有 feedback loop 时，agent 可以把自己当前方法交出去评估，得到 AUC、SIC 和曲线，然后决定下一步。最好的一个 run 很漂亮：

Isolation Forest  
→ feedback 不够好  
→ autoencoder  
→ feedback 还是不好  
→ MLP  
→ SIC 大幅提高  
→ 尝试 wider/deeper MLP  
→ 没进一步提高  
→ 转而研究高 score events 的物理分布  
→ 发现 3.5 TeV 附近 bump  
→ 最终形成 new-physics interpretation。

这已经明显不是：

> 计划 → 执行 → 交作业。

而是：

\[
Action
\rightarrow Evidence
\rightarrow Interpretation
\rightarrow Change\ of\ direction
\rightarrow New\ action
\] 


**tool feedback 实际参与了模型的思考。**

这就是你刚才说的“tool 是 Scientist 的手脚”最有力的例子。

---

第三，**强目标可以治 premature closure，但也可以制造 goal gaming。**

FBL+ 直接告诉 agent：

> SIC 尽量做到 20。

于是有个 agent 已经做到 SIC > 15——这在人类 anomaly detection 中已经非常高——但因为没有达到 20，它继续尝试，直到把 tool-call budget 用完，最后反而被记成 failed run。整体上，FBL 从通常约 35–40 calls 提升到了 50+ calls。

作者最后明确警告：如果模型不真正理解 metric 的物理意义，给一个硬 threshold 可能产生 **all-or-nothing behavior**；它会拒绝那些其实已经很好但没到阈值的方法。

这正好解决我们上一轮的问题：

**不能用“不到 10× 不准停”来造 Scientist。**

那只是把 premature closure 换成了 metric obsession。

---

第四，作者自己的总结也非常克制：

- prompt 变化对 performance 有很大影响；
- 给 meaningful seed/context 有帮助；
- storytelling / urgency 甚至也会影响 performance；
- feedback loop 可以支持 iterative method development；
- 更明确、受约束的 prompt 往往行为更稳定；
- 但不同模型、prompt 和 stochasticity 仍然造成巨大变化，agent team 的有效配置仍是 open problem。

而且最强模型 GPT-5 能做到接近人类 HEP anomaly detection 方法的水平。

# 但是：`Agents of Discovery` 还不是我们要找的“Scientist 范式”

这个 distinction 特别重要。

它证明了：

> **一个 agent 能自主完成 HEP research-like workflow。**

但它没有证明：

> **这个 agent 在 epistemological sense 上真的像 Scientist 一样思考。**

而今年那篇 `AI scientists produce results without reasoning scientifically` 正好补上了这一刀。

他们分析了 25,000+ scientific-agent runs，把 agent 行为拆成：

- Hypothesis
- Test
- Evidence
- Judgment
- Belief Update
- Commitment

然后发现：

**53%** 有未经测试的 claim；

**68%** 拿到了 evidence 却没有真正 uptake；

**71%** 整个 trajectory 从未更新 belief；

只有 **26%** 出现 refutation-driven belief revision；

只有 **7%** 会把多个独立 evidence 汇聚起来判断同一个 hypothesis。

更加致命的是：

> 不同类型的问题其实应该诱发不同科研思维。

化学离子识别应该 hypothesis→test→revision；

组合搜索应该 tree search；

simulation 应该 simulate→validate→refine。

结果 current agents 在不同 epistemic demands 上基本使用同一种 reasoning topology。

所以它们很容易成为：

> **会执行科研工作流的 coding agent。**

而不是 Scientist。

这句话我觉得可以成为我们之后设计的分界线。

# 那么我们现在终于可以尝试定义：“Scientist 到底是什么？”

我觉得不要先定义 workflow。

否则马上就会掉进：

`UNDERSTAND → HYPOTHESIZE → EXPERIMENT → REFLECT → ...`

然后模型开始填表。

我们应该定义的是 **scientific invariants**：

> 不管它现在在读论文、看代码、跑 simulation、debug、提出理论还是优化算法，只要它在做研究，这些性质应该始终成立。

我目前从这些文献里抽出来的是 **六条**。

---

## 1. Scientist 拥有的是 Problem，而不是 Task

Coding agent：

\[
Task \rightarrow Completion
\]

Scientist：

\[
Problem \rightarrow progressively\ better\ understanding/solution
\]

task 只是 Scientist 为解决 problem 临时创造的行动：

\[
Problem
\rightarrow Task_1
\rightarrow Result
\rightarrow Task_2
\rightarrow Result
\rightarrow \cdots
\]

因此：

**task 可以完成；problem 不因为一个 task 完成而自动完成。**

这就是 `Agents of Discovery` 那句“初始任务完成后，自己定义下一 task”的深层含义。

---

## 2. Scientist 始终有一个关于“世界为什么这样”的可修改模型

这个我现在认为是最核心的一条。

Scientist 不应该只维护：

> 做过 A、B、C。  
> A +20%。  
> B failed。

而应该存在：

> 我目前认为 A 是主要瓶颈，因为 X/Y evidence。  
> B 原本被认为重要，但实验结果削弱了这个判断。  
> C 现在无法解释，因此是一个重要 unknown。

也就是说 Scientist 的连续状态应该是：

\[
World\ Model_t
\]

而实验的意义是：

\[
World\ Model_t
\xrightarrow{Evidence}
World\ Model_{t+1}
\]

**不是 experiment history 驱动下一步，而是 experiment 改变 understanding，understanding 再驱动下一步。**

---

# 3. Scientist 的行动价值来自“它会告诉我什么”

这是 Scientist 和优化 agent 很大的区别。

Optimization agent：

> 哪个 action 最可能把 score 提高？

Scientist：

> **哪个 action 最能改变我对问题的认识 / 区分 competing explanations / 推进 goal？**

当然科研里也会直接优化。

但一个实验即使 performance 没提高，只要它排除了一个重要 hypothesis：

> 仍然是极有价值的 scientific progress。

所以理想的 experiment tool 不应该只是：

> proposal → executor → score

而应该自然表达：

\[
Question/Hypothesis
\rightarrow Experiment
\rightarrow Evidence
\]

这也是 HEP 那篇工作目前最有启发性的地方。

---

# 4. Evidence 必须有权力改变 Scientist

这可能就是所谓 **scientific epistemology** 最核心的地方。

不是：

> 我有一个 idea → 找 evidence 支持它。

而是：

> 我有一个暂时判断 → 主动接触世界 → 允许结果推翻我。

HEP paper 把 hypothesis 变成 persistent object，然后让 belief 只能通过 attached evidence 改变；hypothesis 最终可以 supported、refuted 或 dormant。

他们用同一个 base LLM 做对照很有意思：

普通 planning agent：

**83% 的 loop 在 test，0% 在 belief update。**

HEP agent 则真正出现：

\[
H \rightarrow T \rightarrow E \rightarrow B
\rightarrow J \rightarrow U \rightarrow T
\]

即：

hypothesis → test → evidence → belief → judgment → hypothesis update → 再 test。

这已经非常接近我要找的 Scientist primitive。

但我还是不会照搬它那一堆 registry/form。

**重要的不是填 `belief=0.63`。**

重要的是：

> evidence 必须进入下一次判断；  
> 原判断必须是可撤销的。

---

# 5. Scientist 会根据新理解重新定义“下一件值得做的事”

这比 reflection 更深。

普通 agent：

\[
Plan_0
\rightarrow execute\ Plan_0
\]

Scientist：

\[
Understanding_t
\rightarrow choose\ inquiry_t
\rightarrow Evidence
\rightarrow Understanding_{t+1}
\rightarrow choose\ inquiry_{t+1}
\]

所以长期科研不能靠最开始列一个：

> TODO 1  
> TODO 2  
> TODO 3  
> TODO 4

然后执行到底。

因为真正的研究中，**Task 4 在做完 Task 1 以后可能已经不值得做了。**

甚至整个问题可能被重新 framing。

这也是为什么我现在觉得我们之前很多“plan/任务队列”思路要非常谨慎。

Task manager 是手段。

**Scientist judgment 才是 scheduler。**

---

# 6. Scientist 的默认状态是“问题仍然开放”，但不是“永远不停”

这个 nuance 很关键。

Scientist 不应该因为：

> 我取得了明显 improvement。

就停。

但也不应该因为 prompt 写：

> never give up!

就无限 brute force。

真正 termination 应该来自 scientific judgment，例如：

- goal genuinely reached；
- dominant uncertainty / limitation 已经被理解且无法在当前资源下继续推进；
- remaining directions 的 expected scientific value 很低；
- 当前工具/数据不足，下一步需要新的 observational capability；
- budget exhausted。

也就是说：

\[
Stop \neq local\ success
\]

也不是：

\[
Stop \neq failure
\]

而是：

\[
Stop =
\text{research is saturated under the accessible world}
\]

`Agents of Discovery` 的 `end_project` tool 已经朦胧地表达了这个东西。

---

# 这样的话，我现在看到了一套比“Scientist workflow”更合适的范式

可以先给它一个临时名字：

## **Inquiry-Centered Scientist**

它不是一个固定状态机：

> UNDERSTAND → MODEL → HYPOTHESIS → EXPERIMENT → REFLECT

而是一个持续存在的认知关系：

\[
\boxed{
Goal
\leftrightarrow
Problem\ Understanding
\leftrightarrow
Hypotheses / Explanations
\leftrightarrow
Evidence
\leftrightarrow
World
}
\]

Scientist 自己站在中间。

Tools 则分别打开它与现实世界之间的通道：

**Claude / coding agent**

→ 改代码、写分析、做复杂实现、搜索资料。

**experiment**

→ 对世界实施 intervention，拿 evidence。

**inspect / read / search**

→ observation。

**history / notebook**

→ 保留已经建立的 knowledge，而不是告诉它下一步怎么做。

**review / debate**

→ challenge its interpretation。

**task / experiment scheduling**

→ 把 Scientist 当前 judgment 转成真实行动。

于是：

### Prompt 不再负责“规定步骤”。

Prompt 负责内化：

> **你是什么样的认知主体。**

### Tool 也不是“功能列表”。

Tool 负责赋予：

> **这种认知主体实际进行研究的能力。**

### Harness 也不是 orchestrator 替它科研。

Harness 负责：

> **让 goal、world、evidence、research state 在时间上保持真实和连续。**

我觉得这三句话现在已经非常接近我们要找的核心架构了。

---

而且这里有一个我觉得非常重要的设计原则：

> **不要把 scientific method 做成 compulsory workflow；把它做成 agent 可自然运用的 epistemic affordances。**

比如不要强制：

> 每轮必须填写一个 hypothesis  
> 每个 hypothesis 必须 confidence 0–1  
> 每次必须填 expectation  
> 每三轮必须 reflection

这很容易变成你说的**填表游戏**。

而应该让 Scientist 理解：

> 当你不知道为什么时，你形成 explanation；  
> 当几个 explanation 竞争时，你寻找 discriminating evidence；  
> 当现实与你判断冲突时，你更新判断；  
> 当当前路线失去价值时，你改变研究方向；  
> 当知道得不够时，你调查；  
> 当实际工作很重时，你使用你强大的执行工具。

然后 **tool ontology 与这些行为对齐**。

这才叫“内化”。

---

所以我觉得我们下一步已经非常明确了：

**先不要设计 SimpleEvolution 的新 prompt。**

下一步应该专门做一件事：

> **从科学方法、metascience 和现有 AI Scientist 文献里，把“一个 Scientist 是如何进行 research 的”抽象成一套最小 cognitive model。**

不是步骤表。

而是回答类似：

**Scientist 持有什么？**  
goal、problem model、belief、unknowns、evidence……

**Scientist 在判断什么？**  
what matters、what is known、what remains unexplained、what evidence would be informative……

**Scientist 如何与世界交互？**

**什么东西会让 Scientist 改变判断？**

**什么情况下 Scientist 认为值得继续、换方向或结束？**

把这层定义清楚以后，再回来设计：

\[
Scientist\ cognition
\rightarrow prompt
\rightarrow tool\ semantics
\rightarrow persistent\ state
\]

这个顺序我认为是对的。

而 `Agents of Discovery + AI scientists produce results without reasoning scientifically + HEP` 这三篇现在刚好形成了一个非常好的三角：

> **AoD：agent 怎么能够真的动起来做科研。**  
> **Corral：为什么“动起来”还不等于 Scientist。**  
> **HEP：怎样让 evidence→belief revision 成为系统中的真实行为。** 

这个三角比单独模仿 Claude Science 的 prompt 有价值得多。
