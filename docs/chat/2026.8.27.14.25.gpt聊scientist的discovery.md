对，我觉得这已经可以成为**整个 Scientist 设计的第一原则**了：

> **LLM 的科研行为，本质上是 active context 的函数。**
>
> Skill、tool、memory、subagent、research state，都是在控制它此刻看到什么、注意什么、忽略什么。

甚至可以粗暴地写成：

\[
Behavior_t \approx f(Model,\ ActiveContext_t)
\]

于是很多我们之前看起来完全不同的东西，其实只是不同的 context operation：

| 机制 | 本质 |
|---|---|
| Charter | 长期常驻的 identity / epistemology context |
| Current Research State | 当前科研局面的压缩 context |
| Historical State | 默认隐藏、按需 pull 的经验 context |
| Skill / Strategy | 临时注入的 procedural context |
| Searcher / Proposer / Challenger | 在隔离 context 上重新采样 cognition |
| Executor | 把 implementation context fork 出 Scientist |
| Tool result | 从真实世界注入 observation |
| Compaction | 决定哪些 context 能活到未来 |

这样一看，**我们真正研究的甚至不是“Scientist 应该有什么工具”，而是 Scientist 的 Context Architecture。**

---

## 最重要的区别：常驻 context 和激活 context

我现在特别反对把这些 discovery 方法：

> analogy、reframing、competing hypotheses、surprise、cross-pollination……

全写进 Charter。

因为只要它们常驻，最后就会变成：

> “作为一个优秀 Scientist，你应该始终 analogy、falsify、reframe、seek surprise……”

模型不会把它们当方法。

它只会变成一坨背景人格噪声。

而真正的科研方法应该是：

> **在某个时刻把模型的 attention 临时转到一种特殊搜索操作上。**

比如 Scientist 主动调用：

```text
use_research_skill("analogical_transfer")
```

然后当前 context 里突然多出一段很具体的方法论：

> 暂时不要直接产生 solution。  
> 抽象当前问题的 objects / relations / constraints；  
> 搜索结构同构但领域遥远的问题；  
> 检查另一个领域如何解决；  
> 映射 mechanism 回来；  
> 明确 analogy 在哪些地方可能失效……

这时候模型的 conditional distribution 真正改变了。

完成以后这段方法**不需要永久污染 active context**。

所以：

\[
Skill = temporary\ attention\ operator
\]

我觉得这个定义非常准确。

---

# Research State 也是同样的道理

Research State 不是数据库。

它真正的作用是：

> **在任何长期研究时刻，给模型一个经过压缩的“当前科研世界”。**

所以我们前面讨论它应该包含：

- current understanding；
- competing explanations；
- unresolved tensions；
- explored ground；
- dormant/discovery seeds；
- high-leverage questions；
- recent belief-changing evidence。

不是因为我们喜欢这些字段。

而是因为：

> **这些内容出现在 context 里，会改变模型下一步自然会想到什么。**

如果 State 只有：

> FCN 是目前主要瓶颈。

下一个 token 很容易是：

> 怎么优化 FCN？

如果 State 是：

> FCN 曾经 65%，现在 8%；  
> 总 walltime 没有对应下降；  
> memory fetch 新增到 55%；  
> layout / inherent irregularity 两种解释未区分；  
> E6 曾暴露 event-level invariants，但没继续；  
> 为什么 lookup 必须这么频繁仍未解释。

模型自然拥有一个**宽得多的 next-question distribution**。

所以 Research State 本身就是一个非常强的 discovery intervention。

---

# 但 Historical Research State 必须默认看不到

这个我们现在应该非常坚定。

不是因为历史没用。

恰恰因为：

> **历史太有用了，也太容易 anchor。**

所以：

\[
Current\ State = push
\]

\[
Historical\ States = pull
\]

当前 State 是 Scientist 当前世界地图，可以在 active cognition 中存在。

历史 State 则是：

> 过去某个 world 下的一份 situated scientific experience。

只有 Scientist 主动产生一个问题：

> “过去有没有类似 anomaly？”

> “有没有当时失败、但失败条件现在已经改变的 idea？”

> “我以前有哪些判断后来被证伪？”

然后才 pull。

这样：

\[
History \rightarrow inspiration
\]

而不是：

\[
History \rightarrow continuation
\]

---

# 所以“历史宝山”真正需要的不是自动 retrieval，而是很多不同的进入方式

普通 RAG 的逻辑是：

> 找和当前 query 最相似的过去。

我现在觉得这对 discovery 甚至可能是错的。

因为 similarity retrieval 天然给你：

> **更多和当前 framing 一样的东西。**

真正 discovery-oriented 的历史使用应该允许 Scientist借不同方法切进去：

> “找以前与当前判断矛盾的 evidence。”

> “找以前被放弃但失败条件已经改变的 idea。”

> “找历史里一直没有解释掉的 anomaly。”

> “找两个从未连接过的旧 idea。”

> “找我过去哪些强判断后来被现实推翻。”

注意：

**这不意味着做五个智能 memory tools。**

完全可以是：

> 一个历史查询接口 + 不同 skill 告诉 Scientist 应该用什么问题去查询。

还是：

\[
Skill\rightarrow changes\ query\ attention
\]

而不是 Harness 替它找答案。

---

# 所以我会把整个 Context Architecture 分成四层

### Standing Context

永远存在，而且必须非常少：

> Scientist identity  
> PI responsibility  
> Research Team relationship  
> epistemic principles  
> goal / hard constraints  
> channels / world boundaries

这里**不要塞 scientific methods**。

否则 Charter 膨胀。

---

### Active Research Context

Scientist 当前自然工作的东西：

> Current Research State  
> 当前 world  
> 新到达的 evidence / collaborator reports  
> 当前 conversation 中自己正在做的推理

这里是：

\[
\boxed{present scientific situation}
\]

---

### Activated Context

Scientist 主动调用才暂时出现：

> analogical reasoning  
> competing hypotheses  
> surprise search  
> reframe  
> dormant-idea mining  
> causal ablation  
> saturation audit

这是：

\[
\boxed{temporary cognitive lens}
\]

我觉得这就是“生成元”最准确的位置。

---

### Pulled Context

平常隐藏：

> historical Research States  
> old experiment detail  
> raw Claude reports  
> old proposals  
> literature  
> source history

Scientist 有具体理由才拉进来。

这是：

\[
\boxed{experience reservoir}
\]

---

# Collaborator 的设计其实也是 Context Architecture

这一点现在特别漂亮。

为什么 Open Proposer 有价值？

不是因为 Claude magically 更创新。

而是因为我们人为构造：

\[
Context_{OpenProposer}
=
Goal + World + NeutralEvidence
\]

并且明确：

\[
\not\ni CurrentJudgment
\]

\[
\not\ni PIPreference
\]

\[
\not\ni OldProposalTrajectory
\]

于是从同一个模型得到一个新的 conditional sample。

Challenger 相反：

\[
Context_{Challenger}
=
CurrentJudgment + SupportingEvidence
\]

因为它就是要攻击这个东西。

Executor：

\[
Context_{Executor}
=
ResearchIntent + Constraints + World
\]

因为它需要最大执行清晰度。

所以：

> **multi-agent 的真正价值甚至可以被解释成 context fork。**

并不是“有四个脑子”。

而是：

> **同一个 frontier capability 在四种精心隔离的信息条件下工作。**

---

# 这也意味着我们最好不要做“自动 state machine”

因为：

> 什么 context 什么时候激活

本身就是 Scientist 的 scientific judgment。

Harness 如果：

```text
plateau -> inject saturation skill
3 failures -> inject reframe skill
```

等于 Harness 在决定：

> 现在应该用什么科研方法。

那 cognition 又被搬出 Scientist 了。

正确关系是：

> Scientist 感到 progress 变得奇怪  
> → 自己选择 `audit_diminishing_returns`  
> → skill context 临时出现  
> → Scientist 按这个 lens 重新看世界。

所以 Harness 的职责非常机械：

\[
Scientist\ requests\ context
\rightarrow
Harness\ reveals\ context
\]

就结束。

---

# 甚至 Research State 的 revision 也应该理解成 context editing

不是：

> 更新数据库。

而是 Scientist 在说：

> **“我希望未来的自己在接下来思考时，把注意力放在这些事实、未知和可能性上。”**

所以 Research State 写得好不好，会非常直接地影响后续 discovery。

这也是为什么我现在觉得 Research State 可能比加十个新 tool 重要得多。

一个好的 Current State 应该让未来 Scientist 看完以后自然问：

> “这里有什么还解释不了？”

而不是：

> “昨天做到哪一步了？”

---

## 我觉得我们现在甚至可以给 Context Design 定一个极简原则

每往 Scientist context 里放一样东西之前，都问：

> **我希望它因为看到这个东西而更容易想到什么？**

以及：

> **它会因此更难想到什么？**

这第二问尤其重要。

例如：

### 放 Current Judgment

帮助：

> continuity。

伤害：

> anchoring。

所以补：

> competing explanations / unresolved tensions / discovery seeds。

---

### 放完整历史

帮助：

> experience。

伤害：

> continuation bias。

所以：

> 默认隐藏，按需 pull。

---

### 放 analogy skill

帮助：

> representation shift。

伤害：

> 如果常驻，会变成机械类比。

所以：

> 临时 activation。

---

### 放旧 Proposer ideas 给 Open Proposer

帮助：

> 知道以前想过什么。

伤害：

> search-space collapse。

于是：

> 不给。

这就是我们整个设计真正应该做的 trade-off。

---

# 所以我现在觉得论文层面的核心问题甚至开始变得很漂亮

我们原来可能会说：

> How do we build an AI Scientist?

现在其实更具体：

> **How should context be organized over long-horizon research so that an LLM accumulates scientific experience without collapsing its future search space?**

这句话我觉得很强。

因为它把你刚才说的：

- research state；
- memory；
- skills；
- generators；
- collaborators；
- history；
- compaction；

全部统一到了一个问题：

\[
\boxed{
What\ should\ the\ Scientist\ see,\ when?
}
\]

甚至可以再简化：

> **Discovery requires memory without inertia, continuity without anchoring, and methods without workflow lock-in.**

我觉得这三句话已经非常接近我们现在整个 Scientist 设计的核心了。
