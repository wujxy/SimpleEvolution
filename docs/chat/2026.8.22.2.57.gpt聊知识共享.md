# Research Knowledge Sharing Design

## 1. Motivation

在 Research State Evolution 中，多个 Scientist 会围绕同一个 objective world 并行探索不同方向。

当前 Evolution 已经能够通过：

- ResearchState
- Cognitive Transformation
- 多 branch exploration

产生不同研究方向。

然而，随着 branch 数量增加，一个新的问题出现：

> 不同 Scientist 之间如何共享已经获得的研究财富，同时避免形成对已有方向的盲目继承？

如果没有知识共享，系统会出现：

### 1. 重复探索（rediscovery）

多个 Scientist 独立发现相同机制：

```
Scientist A:
发现 memory layout 优化有效

Scientist B:
重新探索 memory layout

Scientist C:
再次探索 memory layout
```

大量计算被消耗在已经验证过的方向。


### 2. 经验孤岛（research isolation）

每个 branch 只能看到：

```
parent node
+
自己的实验历史
```

导致：

- 成功经验无法传播
- 失败经验无法避免重复
- 不同 branch 无法形成更高层理解


因此 Evolution 需要一个独立的 **Research Knowledge Space**。

---

# 2. Design Principle

## Share discoveries, not decisions

知识共享的核心原则：

> 共享客观发现，而不是共享研究方向。


系统应该传播：

```
what happened
```

而不是：

```
what you should do
```

---

错误设计：

```
Finding:

macro-XS optimization is best.

Recommendation:

Try macro-XS next.
```

这会导致：

```
new Scientist
        |
        v
copy previous strategy
```

最终形成路径依赖。


正确设计：

```
Observation:

Macro-XS factorization reduced repeated computation.

Evidence:

Experiment E21

Context:

Applied under lookup structure X.

Limitation:

Not evaluated under architecture Y.
```

Scientist 根据自己的 ResearchState 判断：

```
是否适用于当前问题？
是否值得进一步探索？
```

---

# 3. Relationship with ResearchState

Knowledge Space 与 ResearchState 是两个不同层次。

## ResearchState

属于单个 Scientist。

表示：

> Scientist 当前对于问题的理解模型。


例如：

```
ResearchState:

Current belief:

FCN overhead mainly comes from repeated invariant computation.

Evidence:

Experiment A
Experiment B
```


---

## Knowledge Space

属于整个 Research Group。

表示：

> 整个系统曾经观察到的事实和经验。


例如：

```
Knowledge:

Finding 001:

Invariant hoisting improved performance.

Finding 002:

Memory layout change reduced cache miss.

Finding 003:

SIMD optimization failed because workload is memory bound.
```


---

二者关系：

```
             Knowledge Space
                    |
                    |
              observations
                    |
                    v

          Scientist ResearchState

                    |
                    |
              interpretation

                    |
                    v

              Proposal
```


Knowledge 提供材料。

ResearchState 产生理解。

二者不能混合。

---

# 4. Knowledge Object

Knowledge 不保存完整 branch。

它保存经过实验验证后的研究发现。

一个 Knowledge Object 包含：

```
Finding

{
    mechanism:
        underlying mechanism

    observation:
        observed phenomenon

    context:
        where it was observed

    evidence:
        related experiments/nodes

    limitation:
        known boundary conditions
}
```


例如：

```
Finding:

Mechanism:
Reduce redundant computation.

Observation:
Removing invariant FCN calculation improves throughput.

Context:
XSBench lookup kernel.

Evidence:
Node A
Experiment E12

Limitation:
Only verified for current data layout.
```

---

# 5. Knowledge Lifecycle

Knowledge 不应该在 proposal 阶段产生。

因为 proposal 只是：

```
hypothesis
```

不是：

```
knowledge
```


生命周期：

```
ResearchState

      |
      v

Proposal

      |
      v

Experiment

      |
      v

Observation

      |
      v

Finding

      |
      v

Knowledge Space
```


只有经过 objective experiment 验证的信息，才成为共享财富。

---

# 6. Knowledge Access

Knowledge Space 不应该主动注入 Scientist。

否则会形成：

```
Knowledge retrieval
        |
        v
solution imitation
```


正确模式：

Scientist 在需要时查询。


例如：

## 情况1：避免重复

Scientist:

```
I want to optimize lookup algorithm.
```

查询：

```
related findings
```

发现：

```
Existing finding:

Lookup structure optimization already explored.

Result:
small improvement only.
```

于是调整方向。


---

## 情况2：扩展探索空间

Scientist:

```
I believe computation is bottleneck.
```

查询：

```
related mechanisms
```

发现：

```
Previous finding:

Memory locality significantly affects performance.
```

产生新的 ResearchState：

```
Maybe computation bottleneck is caused by data movement.
```

---

# 7. Knowledge Sharing and Diversity

Knowledge Sharing 的目的不是减少探索。

相反，它提升有效探索。


没有共享：

```
A:
try method X

B:
try method X

C:
try method X
```

共享后：

```
A:
method X successful

B:
method X already explored

B:
explore method Y
```

因此：

```
Knowledge Sharing

        ↓

remove redundant exploration

        ↓

increase available exploration budget

        ↓

increase diversity
```


---

# 8. Relationship with Cognitive Transformation

Knowledge Sharing 和 Transformation 解决不同问题。


## Knowledge Sharing

解决：

> 我是否重复别人已经知道的事情？


类似：

组会交流。


---

## Cognitive Transformation

解决：

> 我是否被自己的理解限制？


类似：

导师指导。


---

关系：

```
Scientist

   |
   |
   +---- query Knowledge
   |
   |
   +---- apply Transformation
   |
   |
New ResearchState
```

Knowledge 提供外部事实。

Transformation 改变内部视角。

---

# 9. Relationship with Frontier

Frontier 和 Knowledge Space 不负责同一件事情。


Frontier:

```
Which node should continue?
```

根据：

```
objective metrics
gate
Pareto
```


Knowledge:

```
What has the research group learned?
```

根据：

```
experiment evidence
```


关系：

```
                 Knowledge Space
                       ^
                       |
                 experiments
                       |
ResearchState → Proposal → Experiment → Node
                                      |
                                      v
                                  Frontier
```

---

# 10. Core Philosophy

Research Knowledge Sharing 的目标不是构建一个：

```
best solution database
```

而是构建：

```
collective scientific memory
```

它应该帮助 Scientist：

- 避免重复过去
- 理解已有事实
- 发现新的解释空间

但不能替代 Scientist：

- 选择研究方向
- 判断问题本质
- 形成新的 ResearchState

最终：

```
Knowledge provides memory.

Transformation provides creativity.

Experiment provides truth.

Frontier provides selection.
```

这四者共同形成一个可持续演化的 autonomous research organization。

## 1. 首先区分三个 merge，我认为是正确的

之前我们说“不要 merge”，其实容易让人误解。

更准确：

### (1) Evidence merge —— 必须有

这是：

> 我们整个课题组知道发生过什么。

例如：

Branch A：

```
Node A

intervention:
remove RNG initialization

result:
+20%
```

Branch B：

```
Node B

intervention:
change layout

result:
+15%
```

这些应该进入共同历史。

因为这是客观事实。

---

### (2) Belief merge —— 不应该由系统做

这是：

> 两个学生的理解能不能融合？

例如：

学生 A：

```
瓶颈是计算重复
```

学生 B：

```
瓶颈是内存访问
```

系统不能说：

> 综合一下，你们都是对的。

因为这仍然是解释。

应该由新的 Scientist：

- 查看 evidence
- 形成自己的 ResearchState

---

### (3) World merge —— 必须实验验证

这个是最重要的。

假设：

A:

```
优化计算
+20%
```

B:

```
优化内存
+15%
```

直觉：

```
A+B = +35%
```

但现实可能：

情况1：

```
A减少计算

B减少memory traffic

互补

=> +40%
```

情况2：

```
A改变数据结构

B依赖旧数据结构

冲突

=> +5%
```

情况3：

```
两个优化消除了同一个瓶颈

=> +20%
```

所以不能：

```text
branch A patch
+
branch B patch
=
new node
```

这违反 experiment-driven selection。

```

```


# 8. 最终论文层面的意义

这个机制解决的不是：

“如何保存历史”。

而是：

**如何让多个 autonomous researchers 形成 collective intelligence，同时避免 collective bias。**

这是一个非常有价值的问题。

因为：

- 没有共享 → 多个孤立 agent，重复劳动；
- 共享结论 → 群体快速收敛，失去探索；
- 共享事实 → 保留积累，同时允许重新解释。

所以最终设计哲学可以总结：

> A research organization should accumulate evidence, not beliefs.

这句话我觉得甚至可以作为整个 Research Knowledge Exchange 的设计原则。
