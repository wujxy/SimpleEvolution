明白，而且我觉得你这里实际上指出了比“frontier 多样性”更深一层的问题：

**多样性不是只有 selection 端的问题，generation 端同样会塌缩。**

之前我们容易把问题简化成：

但你的实验暴露的是另一半：

```
diversity collapse
=
selection collapse
+
generation collapse
```

两个问题缺一不可。

## 你说的“继承客观世界，而不是继承父亲方向”非常关键

现在 naive tree evolution 的隐含逻辑：

```
Node A
  |
  | "这个方向有效"
  |
Child A1
  |
  | "继续优化这个方向"
  |
Child A2
  |
  | "继续优化 A1"
```

这实际上不是 evolution。

这是：

```
hill climbing with memory
```

因为 child 继承的是：

> 父节点的解释

而不是：

> 父节点产生的事实变化


真正应该是：

```
Node A
 |
 | 继承：
 | - 当前代码状态
 | - objective metrics
 | - experiment evidence
 |
 v

Scientist

重新理解：

"现在世界是什么样？"

然后：

A1:
继续当前方向

A2:
换一个机制解释

A3:
挑战问题定义

A4:
寻找完全不同瓶颈
```

所以 child 的 parent 应该是：

```
world state parent
```

不是：

```
idea lineage parent
```

## 你的“财富继承”比喻非常准确

现在的 tree：

```
发现油田
  |
  |
挖深一点
  |
  |
继续挖
  |
  |
继续挖
```

问题：

大家共享一个假设：

> 这里还有油。


但是科研真正应该是：

```
发现油田
 |
 |
有人继续开采
 |
有人研究：
是不是还有别的油田？
是不是这个油田只是表象？
是不是能源问题根本不是油？
```

因为父节点的成功只证明：

```
intervention worked
```

不证明：

```
underlying explanation is complete
```

## 这也是为什么 ResearchState 必须和 Node 分离

如果没有 ResearchState：

Node:

```
speed improved
```

下一代 Scientist 很自然：

```
继续优化导致 speed improvement 的东西
```

因为它看到的是：

```
父亲成功
```

而不是：

```
为什么父亲成功？
```

加入 ResearchState 后：

父节点保存：

```
Working model:

"macro_xs lookup dominates because search operation is expensive"

Evidence:

experiment +20%
```

下一代看到：

```
事实:
speed +20%

解释:
父 Scientist 认为原因是 search operation
```

然后它可以做：

```
接受:
继续优化 search

或者：

质疑:
真正原因是不是 memory access?

或者：

质疑:
为什么需要 lookup?

或者：

质疑:
算法结构是否合理?
```

这才是真正的“站在巨人的肩膀”。

## 所以 Transformation 的作用也更清楚了

之前说 transformation 是 mutation。

但现在我觉得应该更准确：

它不是 mutation operator。

它是：

**anti-inheritance operator**

即：

防止 child 盲目继承 parent 的认知惯性。


比如：

父：

```
working model:
lookup search is bottleneck
```

Transformation：

```
question abstraction boundary
```

产生：

```
maybe lookup itself is unnecessary
```

这不是随机变异。

它是在打破：

```
parent belief → child belief
```

这个链。

## 那 frontier 应该做什么？

我觉得现在分工变得很清楚：

### Proposer / ResearchState：

负责：

```
search space generation
```

回答：

> 我们还应该探索哪些可能世界？


### Frontier：

负责：

```
survival selection
```

回答：

> 哪些真实世界状态值得继续投入资源？


不能反过来。

如果让 frontier 负责产生 diversity：

就会变成：

```
scheduler:
你们必须探索不同方向
```

但是它不知道什么叫方向。

## 这也解释为什么“proposal_slots=3”不一定解决问题

假设：

```
一个 Scientist:

proposal 1:
optimize cursor

proposal 2:
optimize cursor better

proposal 3:
optimize cursor even better
```

数量增加没有意义。

真正需要：

```
proposal 1:
cursor optimization

proposal 2:
vectorization

proposal 3:
algorithm replacement
```

所以 diversity 的单位不是：

```
proposal count
```

而是：

```
independent ResearchState / worldview count
```

---

## 这让我觉得你的 ResearchState 设计还有一个非常重要的约束

一个 child node 启动时：

不要给：

```
parent ResearchState
```

作为答案。

而应该给：

```
parent ResearchState + objective evidence
```

然后要求：

```
Scientist reconstruct its own ResearchState
```

否则：

ResearchState 会变成新的“财富”。

最后又会：

```
RS1
 |
 RS2
 |
 RS3
```

继续继承错误。


---

所以我现在会重新表述 SimpleEvolution 的核心问题：

不是：

> 如何让树保持宽度？

而是：

> 如何让每个新 Scientist 在继承真实世界进展的同时，避免继承前人的认知偏差？


然后：

- ResearchState：保存认知
- Transformation：扰动认知
- Evidence：保存事实
- Frontier：选择现实

四者组合才形成真正的 evolutionary research。

你这个 top-k 实验其实非常关键，因为它证明了**没有 cognitive diversity，objective selection 最终只会放大已有成功方向，而不是产生新研究方向。**
