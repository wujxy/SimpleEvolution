综合前面的审查，最终需要改的地方我归纳成三类：**删/改措辞、补充 Claude 定位、压缩重复内容。**

---

# 一、需要修改的不妥措辞

## 1. Claude 不要被定义成“executor”，而应该是“超级执行助手”

### 当前：

> It is the strongest executor there is

问题：

“executor”容易让模型形成：

```
Scientist = 思考者
Claude = 干活的人
```

过度二元化。

你的真实关系：

```
Scientist = 研究负责人
Claude = 世界级执行能力 + 外部能力入口
```

建议改：

> It is a world-class execution assistant / execution engine.

强调：
- 它负责把 Scientist 的想法变成现实；
- 不是普通执行器。

---

## 2. 减少“Claude 比你强”的重复

当前多处：

- far better than you
- far stronger than your own hands
- better and faster than you would
- strongest coding agent there is

问题：

重复不会增强效果，反而会让模型形成：

> Claude 很强，但是只是一个工具。

建议保留一次强定位即可：

> Claude Code possesses world-class capability in implementation, debugging, measurement, literature search, and long-horizon technical work.

后面直接讲如何使用。

---

## 3. 删除或修改：

> It is your amplifier, not your sword-bearer

问题：

`sword-bearer` 这个隐喻容易引入奇怪角色关系。

建议：

> It amplifies your ability; it does not replace your scientific judgment.

更直接。

---

## 4. 修改：

> what question this lab is asking

问题：

太绝对。

Claude 可以帮助重新理解问题、提出新的 framing。

不是：

“Claude 不准碰问题”。

而是：

“最终研究问题归 Scientist 所有”。

建议：

> ownership of the research question and final scientific judgment

---

## 5. 修改：

> It executes exactly what the brief says

问题：

低估 Claude Code。

Claude Code 不是机械执行：

Scientist：

> 优化这个 kernel

Claude：

应该自己：

- 阅读代码；
- 找实现位置；
- debug；
- 选择实现方式；
- benchmark。

建议：

> It follows the intent of your brief and autonomously solves the implementation details required to achieve it.

---

# 二、必须增加：Claude 四大能力入口

现在虽然有：

> consult / debate / work / review

但是没有足够强调。

应该明确写成 Claude 的核心使用方式：

---

## 1. Consult — knowledge acquisition

用途：

Scientist 缺少外部知识。

包括：

- 文献搜索；
- prior art；
- 算法调查；
- 领域知识。

重点：

Claude 提供：

- 信息；
- 来源；
- 事实。

不提供：

- 最终研究方向。

例如：

错误：

> I think JUNO should use Transformer.

正确：

> Transformer-based waveform reconstruction methods include...

---

## 2. Work — execution

Claude 负责：

- coding；
- refactor；
- instrumentation；
- experiment；
- debugging；
- benchmark。

Scientist：

决定：

> 做什么。

Claude：

负责：

> 怎么实现并验证。

---

## 3. Debate — critic

这是 Scientist 思考辅助。

用途：

当 Scientist 有 hypothesis：

> “我觉得这个方向可能有效。”

调用 Claude：

- challenge；
- counterexample；
- alternative explanation；
- falsification experiment。

但是：

Claude 不拥有 conclusion。

---

## 4. Review — verification

用途：

提交前：

- review diff；
- 找 bug；
- 找遗漏；
- 攻击验证逻辑。

Claude 是第二双眼睛。

但是：

最终 verdict 属于 harness / Scientist。

---

# 三、需要降低重复，缩短上下文

现在最大的问题：

Claude 定位出现太多次。

重复位置：

1. System Prompt：
   - line 16
   - line 47-63

2. Skill：
   - line 148-160

3. Tool schema：
   - consult
   - work

建议结构：

---

## System Prompt

只定义一次：

```
Claude Code is your world-class research assistant and execution engine.

It helps you:
- acquire information,
- execute technical work,
- challenge ideas,
- review conclusions.

You own:
- research direction,
- interpretation,
- final judgment.
```

---

## Skill

不要重复人格。

只保留：

```
Claude usage methods:
consult / work / debate / review
```

---

## Tool schema

只描述接口。

不要再次写：

> strongest coding agent there is

---

# 四、最终 Claude 关系模型应该固定为一句话

整个 prompt 最核心的一句话应该变成：

> Claude is a world-class research assistant and execution engine: it expands what you can investigate and accomplish, but it does not own the research question or final scientific judgment.

这句话基本覆盖全部。

---

# 五、修改后的整体方向

现在版本：

> 一个科学家 + 一个超级程序员助手

修改后：

> 一个科学家 + 一个世界级研究执行助手

区别：

前者：

```
Scientist:
想方向

Claude:
写代码
```

后者：

```
Scientist:
负责研究

Claude:
搜索信息
讨论想法
实现方案
执行实验
检查结果

Scientist:
综合证据，决定相信什么
```

这才和你设计的 Scientist 架构完全一致。你现在不需要再增加更多“科学方法论”，主要就是把 Claude 的角色从 **“最强 coding worker”调整成“最强 external capability layer”**。
