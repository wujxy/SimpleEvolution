可以。现在已经足够收束了，而且我建议把过去那套 Scientist/席位体系先放到一边，把新设计写成一个**非常简单的 Multi-Agent Evolution Laboratory**：强 coding agent 负责科研，SimpleEvolution 只负责实验室和演化。

# SimpleEvolution：Multi-Agent Evolution Laboratory 设计

## 1. 问题

过去的 Scientist 架构虽然拥有 Executor、Proposer、Challenger、Reviewer、Searcher 等多个席位，但真实运行暴露出一个根本问题：

> 系统仍然是一颗 Scientist 脑，通过多个角色函数串行处理自己的 worldview。

Scientist 负责理解问题、形成判断、决定分工、撰写 brief、调用席位、读取结果、再形成新的判断。

因此其它席位虽然模型能力很强，却实际上成为 Scientist 的工具：

- 研究方向主要由 Scientist 决定；
- 席位往往围绕 Scientist 已形成的 framing 工作；
- 多席位并不等于多份独立认知；
- Reviewer / Challenger 可以高质量地验证一个错误 framing；
- 并行度取决于 Scientist 是否主动 fan-out；
- 单个 Claude Code 反而可以表现出更强、更连续的自主科研能力。

目标因此发生变化：

> 不再试图制造一个更聪明的 Scientist，而是让多个已经很强的 autonomous coding agents 真正成为实验室里的独立研究员，并通过 Evolution 组织它们共同探索。

---

# 2. 核心设计

SimpleEvolution 不负责替研究员思考。

它只提供：

> **World + Population + Shared Research Record + Evaluation + Evolution。**

研究本身由现成的强 autonomous coding agent 完成。

基本结构：

```text
                         Supervisor
                population / node allocation
                            │
             ┌──────────────┼──────────────┐
             │              │              │
           Node A          Node B         Node C
          world A         world B        world C
             │
       ┌─────┼─────┐
       │     │     │
      R1    R2    R3
   Claude Claude Claude
    Code   Code   Code
       │     │     │
       └── findings ──→ Shared Research Record
       │     │     │
       ↓     ↓     ↓
    candidate child worlds
             │
          evaluator
             │
          new nodes
```

其中：

- **Node 是研究世界。**
- **Claude Code 是研究员。**
- **Shared Research Record 是实验室公共知识。**
- **Supervisor 管 population 与 evolution。**

---

# 3. Node：共同出发的研究世界

一个 Node 表示一个已经成立的 world state，例如：

```text
Node N
git SHA: abc123
objective: 147 ms/event
gate: pass
parent: N7
```

Node 本身是冻结的。

多个 researcher 可以从同一个 Node 出发，但每个人拥有自己的独立 workspace：

```text
                 Node N
              /    |    \
            R1     R2     R3
           fork   fork   fork
```

因此：

> 多个 researcher 共享同一个现实起点，但不共享同一个 mutable workspace。

任何 researcher 的实验都首先发生在自己的世界中。

只有经过 evaluator 验证的结果，才有资格成为新的 Node。

---

# 4. Researcher：直接使用强 Coding Agent

Node 中入住的 researcher 第一版直接使用：

> **Claude Code。**

不重新实现自己的 ReAct loop。

原因不是 Claude Code 永远是最终答案，而是当前研究问题不是：

> 如何重新制造一个 autonomous coding agent？

而是：

> 多个已经很强的 autonomous coding agents 能否通过共享研究和 Evolution 形成比单 agent 更强的科研能力？

因此保持 researcher 本体固定，可以得到最干净的比较：

```text
1 × Claude Code
vs
N × Claude Code + Shared Research + Evolution
```

每个 researcher 拥有最大的科研自主权，可以自行：

- 阅读源码；
- 理解问题；
- profile；
- 搜索信息；
- 形成 hypothesis；
- 编写代码；
- 做小实验；
- 跑 evaluator；
- 推翻自己的判断；
- 改变研究方向；
- 阅读其他 researcher 的 findings；
- 吸收其他人的代码；
- 持续研究直到 session 结束。

SimpleEvolution 不规定：

```text
propose
→ plan
→ code
→ review
→ reflect
```

等固定科研流程。

Researcher 自己决定如何研究。

---

# 5. Research diversity

多个相同 Claude Code 从相同 world 出发，并不天然产生足够 diversity。

因此 Supervisor 可以在给 Node 分配 researcher 时附加一个**轻量 research seed / mutation factor**。

例如：

```text
R1: whole-goal optimization
R2: representation shift
R3: assumption inversion
R4: negative space
R5: question reframing
```

这些 seed 只规定：

> 从什么角度开始看问题。

而不规定：

> 应该得出什么答案；
> 应该修改什么代码；
> 应该采用什么具体路线。

Discovery Skills 因此可以自然解释为：

> **Evolution 的 mutation operators。**

它们负责增加研究 population 的初始差异，而不是控制 researcher 的完整 workflow。

---

# 6. Shared Research Record：共享事实，不共享大脑

多个 researcher 必须能够知道别人已经做过什么。

但不能把 Supervisor 的 worldview 实时灌给所有 researcher。

因此明确区分：

## Shared Research Record

实验室公共事实。

包括：

- 做过什么实验；
- 使用了什么 world / commit；
- 测到了什么结果；
- 哪些 gate pass / fail；
- 哪些 hypothesis 得到支持或反驳；
- 哪些路线失败；
- 有哪些可复用代码；
- 当前有哪些 active research trajectories。

所有 researcher 和 Supervisor 都可以读取。

## Researcher Notebook

每个 researcher 自己的连续认知。

记录：

- 自己当前怎么理解问题；
- 自己正在追什么；
- 自己尚未验证的判断。

不自动广播给其他 researcher。

## Supervisor View

Supervisor 对整个 population / tree 的判断。

例如：

- 哪些 Node 值得继续投入；
- 哪些方向已经拥挤；
- 哪些 Node 出现 breakthrough；
- 哪里需要增加 diversity。

它服务于 allocation。

它不是公共真理，也不默认成为其他 researcher 的前提。

原则是：

> **事实共享，认知不强制同步。**

---

# 7. Finding：实验室协作的基本单位

Researcher 不是把完整 session 发给别人。

真正共享的是简洁的 finding。

例如：

```text
Node: N17
Agent: A3

Tried:
Reduced Minuit maxcalls to 40.

Result:
Speed improved by 18%, but CONSISTENCY failed.

Finding:
This experiment does not establish that call-count control is impossible.
It only rules out this aggressive setting.

Code:
commit abc123
```

Finding 主要回答：

- 我试了什么；
- 发生了什么；
- 有什么证据；
- 它意味着什么；
- 相关代码在哪里。

它不是必须正确的最终结论。

别的 researcher 可以：

- 相信它；
- 怀疑它；
- 重复它；
- 扩展它；
- 忽略它。

---

# 8. Finding 的读写方式

不依赖一次性的 `claude -p` prompt 让 Claude Code “记得合作”。

每个 researcher 的环境中常驻一个非常短的 Lab Protocol。

核心要求只有两件：

### 写

当得到对其他 researcher 有复用价值的信息时，写入 shared findings。

### 读

当准备开始一个明显新的研究方向时，检查最近出现的新 findings。

不要求：

> 每个 action 都同步所有人的进展。

因此：

```text
Researcher experiment
       ↓
得到有价值结果
       ↓
write finding
```

和：

```text
一个 trajectory 阶段结束
       ↓
准备决定 next direction
       ↓
read new findings
       ↓
自己决定是否吸收
```

Shared store 实时更新。

Researcher context 不实时强制同步。

这样既得到协作，又避免所有 agent 很快收敛成同一个 worldview。

第一版只使用：

> Claude Code + 常驻 Lab Protocol + shared filesystem/findings。

如果真实运行证明 Claude 经常忘记写 finding，再考虑极轻量 lifecycle reminder。

不提前重新制造 ReAct loop。

---

# 9. Code sharing 与 Merge

研究进展共享和代码合并是两件不同的事情。

## 不自动 merge researcher 的世界

Researcher A 和 B 从 Node N 出发：

```text
N
├── A → C1
└── B → C2
```

C1 和 C2 保持独立。

Node N 本身不改变。

这样 evaluator 才能清楚知道：

> 哪个 intervention 导致了哪个结果。

---

## Researcher 可以主动吸收别人的成果

例如：

```text
C1:
cache optimization
131 ms

C2:
Minuit optimization
125 ms
```

Researcher C 看到 shared finding 后认为两者可能正交。

它可以自己：

```text
checkout C1
inspect C2
cherry-pick / rewrite / merge
resolve conflict
run evaluator
```

产生：

```text
C3:
cache + Minuit
108 ms
gate pass
```

于是 C3 成为新的 candidate world。

原则：

> **代码可以共享，但继承由 researcher 自己决定；任何组合都必须重新经过 evaluator。**

---

# 10. Tree 与多来源继承

第一版没有必要把 world graph 做成复杂 DAG。

仍然可以规定：

```text
parent(C3) = C1
```

同时记录：

```text
incorporates = [C2]
```

也就是说：

> **World evolution 保持简单树结构；research provenance 可以记录多来源。**

这样既保留可解释的 world lineage，也允许 researcher 横向组合其他人的成果。

---

# 11. Supervisor

过去 Scientist 同时承担：

- 研究；
- 理解；
- framing；
- delegation；
- critique；
- integration；
- world management。

这是中心脑问题的来源。

新架构中的 Supervisor 职责非常窄：

> **管理 research population 和 evolution。**

它主要判断：

### Node allocation

哪个 Node 值得投入更多 researcher？

### Research diversity

某个 Node 上是不是所有 researcher 都挤进了同一种方法？

是否值得加入新的 mutation seed？

### Resource allocation

某个方向：

- 应继续；
- 加大投入；
- 降低投入；
- 停止繁殖？

### World evolution

哪些 candidate world 通过 evaluator，可以成为正式 Node？

### Population transition

一个 breakthrough Node 出现后，是否应该让新的 researcher 从它重新出发？

Supervisor 管：

> **哪里值得放 researcher。**

Researcher 管：

> **进去以后怎么研究。**

Supervisor 不负责：

> “A1 下一步应该修改 OMILRECV2.cc 第 437 行。”

---

# 12. 一个完整 Evolution Cycle

例如当前：

```text
Node N
147 ms/event
```

Supervisor 给它 4 个 researcher：

```text
R1 — whole-goal optimization
R2 — representation shift
R3 — assumption inversion
R4 — negative space
```

四个人独立研究。

期间：

```text
R1 → finding F1 → candidate C1 = 131 ms
R2 → finding F2 → no improvement
R3 → finding F3 → discovers call-count possibility
R4 → finding F4 → alternative architecture
```

R1 看到 F3：

> 这个方向可以和自己的 cache 改动结合。

于是继续研究，吸收 R3 的代码/idea：

```text
C1 + F3
↓
C5
108 ms
gate pass
```

Evaluator 接受 C5。

于是：

```text
N
└── C5
```

Supervisor 发现 C5 是 breakthrough：

```text
allocate 4 new researchers to C5
```

Evolution 继续。

---

# 13. 与旧 SimpleEvolution 的关系

旧设计：

```text
Node
↓
Scientist / Proposer
↓
Proposal
↓
Executor
↓
Experiment
↓
Child Node
```

新设计：

```text
Node
↓
Multiple Autonomous Researchers
↓
Research trajectories
↓
Findings + Experiments + Code
↓
Candidate worlds
↓
Child Nodes
```

最大的变化不是“增加更多 agent”。

而是：

> **Evolution 的变异单位从 Proposal 变成完整 autonomous research trajectory。**

以前：

> 一个 agent 想出一个 idea，再让另一个 agent 实现。

现在：

> 一个 coding agent 自己在真实 world 中长期研究，直到产生新的 world。

因此 Proposal 不再是 evolution 的核心中间实体。

---

# 14. 不再强调固定 Cognitive Roles

Executor / Proposer / Challenger / Reviewer / Searcher 不再作为整个 laboratory 的核心拓扑。

原因是：

> 一个完整 researcher 应该能够在自己的 trajectory 中自然完成这些科研动作。

它可以：

- 提新 hypothesis；
- 搜资料；
- 写代码；
- 质疑当前判断；
- 验证结果。

如果需要增加 diversity，可以给 researcher 不同 research seed。

但不再认为：

> 五种角色 = 五颗独立研究脑。

真正的独立性来自：

- 独立 context；
- 独立 workspace；
- 独立 research trajectory；
- 不同 research seed；
- 横向共享事实。

---

# 15. Harness 的边界

SimpleEvolution 不做 Harness 科研。

它不规定：

- researcher 怎样思考；
- researcher 什么时候必须反思；
- researcher 必须经历哪些阶段；
- researcher 必须调用哪些 skills；
- researcher 应该如何形成 hypothesis；
- reviewer/challenger 应该什么时候出现。

它只提供研究员自身没有的实验室基础设施：

```text
Nodes
Independent workspaces
Shared findings
Active research visibility
Code provenance
Evaluator
Population allocation
Evolution
```

一句话：

> **Claude Code 负责科研；SimpleEvolution 负责让很多 Claude Code 处在一个能共同进化的实验室里。**

---

# 16. 最终设计原则

整个架构可以压缩成六句话：

1. **一个 Node 是一个冻结的 research world。**
2. **一个 Node 可以入住多个完整 autonomous coding agents。**
3. **每个 agent 拥有独立 workspace、context 和最大科研自主权。**
4. **所有 agent 横向共享实验事实和 findings，但不强制共享 worldview。**
5. **agent 可以主动吸收其他人的代码和发现，组合结果重新经过 evaluator 后产生新 Node。**
6. **Supervisor 只管理 population、资源和 evolution，不替 researcher 研究。**

因此最终形态不是：

> Scientist + 一群手下。

而是：

> **一个由多个强 autonomous researchers 构成的演化实验室。**

这版我认为已经可以作为下一阶段的设计基线了。最重要的是先冻结：*om*不再继续补 Scientist 身份、角色、流程和 skill ontology，下一步应该验证这个最简单的 autonomous-researcher population 能不能真的跑出协作和 evolution。**
