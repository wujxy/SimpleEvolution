下面把讨论收束成一份设计层总结。重点不是工程实现，而是明确 **Scientist 应该是什么、Claude 在其中扮演什么角色、两者如何协作**。

---

# Scientist Agent Design: Research State Driven Autonomous Research

## 1. 核心目标：从 Coding Agent 转变为 Scientist

当前大多数 coding agent 的核心循环：

```
Task
 ↓
Inspect Code
 ↓
Modify Code
 ↓
Run Test
 ↓
Accept / Reject
```

它优化的是：

> 如何产生一个有效的代码修改。

但科研任务的核心不是代码，而是对问题的理解不断深化。

一个 Scientist 的核心循环应该是：

```
Research World
      ↓
Understand Problem
      ↓
Form Hypothesis
      ↓
Acquire Evidence
      ↓
Update Understanding
      ↓
Refine Research Direction
      ↓
Repeat
```

Scientist 的目标不是直接产生 patch，而是：

> 建立、维护并不断修正自己对研究对象的理解模型。

---

# 2. Research State：Scientist 的核心状态

Scientist 不应该主要记忆：

- 做过哪些修改；
- 跑过哪些命令；
- 哪个 patch 更好。

而应该维护：

## Research State

即：

> 当前 Scientist 对 Research World 的理解。

包括：

### 1. Problem Understanding

当前认为：

- 问题本质是什么；
- 影响因素有哪些；
- 关键限制在哪里。

例如 waveform reconstruction：

```
当前理解：

误差可能主要来自：
1. detector response mismatch
2. waveform information loss
3. reconstruction model bias
```

---

### 2. Hypothesis

Scientist 对问题提出解释：

```
如果 response mismatch 是主要瓶颈，

那么改善 response model 应该显著提升 reconstruction accuracy。
```

Hypothesis 不是 proposal。

Proposal 是行动。

Hypothesis 是：

> 为什么这个行动值得做。

---

### 3. Evidence

实验结果不是简单：

```
CNN +3%
```

而应该成为：

```
Evidence:

CNN improves reconstruction.

Interpretation:

Waveform contains information
not captured by current representation.

Implication:

Representation limitation may exist.
```

---

### 4. Unknowns

Scientist 必须知道自己不知道什么。

例如：

```
已知：
noise reduction improvement limited

未知：
remaining error comes from
physics model or representation
```

未知决定下一步研究。

---

# 3. Scientist 的理想研究行为

一个 Scientist 不应该：

```
看到任务
→ 马上改代码
```

而应该：

---

## Phase 1：理解（Understand）

进入 Research World：

- 阅读源码；
- 分析数据；
- 理解 pipeline；
- 调研背景知识。

目的：

形成初始问题模型。

---

## Phase 2：建模（Model）

提出：

- 当前解释；
- 候选机制；
- 假设。

例如：

```
我认为主要限制来自 A。

理由：
已有实验 B，
源码结构 C。
```

---

## Phase 3：调查（Investigate）

根据当前 Research State 决定：

需要什么信息：

- 查论文；
- 查已有方法；
- 分析源码；
- 与其他观点讨论。

调查不是为了得到答案，而是减少不确定性。

---

## Phase 4：实验（Experiment）

实验不是：

> 找一个成功优化。

而是：

> 获取能够区分不同解释的 evidence。

例如：

错误：

```
尝试 CNN，看是否提升。
```

正确：

```
假设：
representation 是瓶颈。

实验：
比较不同 representation。

目的：
判断 representation 是否贡献主要误差。
```

---

## Phase 5：更新 Research State

实验之后：

不是：

```
实验完成。
```

而是：

```
原假设：
部分正确。

新增证据：
...

新的未知：
...

下一步：
...
```

科研的进步来自 Research State 的变化。

---

# 4. Claude 的定位：Scientist 的能力扩展，而不是 Scientist 本身

Claude 不应该替代 Scientist。

Scientist 负责：

- 问题理解；
- 研究方向；
- hypothesis；
- evidence interpretation；
- 最终判断。

Claude 提供：

- 强大的执行能力；
- 信息获取能力；
- 分析能力。

关系：

```
Scientist
    |
    |  Research State
    |
    ↓

Claude Capability Layer

```

---

# 5. Claude 应作为多方面 Assistant 使用

Claude 不是单一 coding tool。

它类似科研中的：

- 师兄；
- 工程助手；
- 文献助手；
- 审稿人。

---

## 1. Literature / Investigation Assistant

作用：

扩展 Scientist 的知识边界。

任务：

- 搜索论文；
- 总结方法；
- 分析领域知识；
- 比较已有方案。

输出：

不是答案，而是：

```
Evidence / Information
```

由 Scientist 判断是否改变 Research State。

---

## 2. Work / Engineering Assistant

作用：

执行 Scientist 已经设计好的实验。

例如：

Scientist：

```
我要验证 hypothesis X。

需要实现 experiment Y。
```

Claude：

负责：

- 写代码；
- 修改工程；
- debug；
- 运行实验。

但是：

Claude 不决定：

“应该研究什么”。

---

## 3. Review Assistant

作用：

检查研究逻辑。

例如：

Scientist：

```
CNN提升说明 representation 是瓶颈。
```

Review Claude：

挑战：

```
是否存在其它解释？
实验是否真的验证 hypothesis？
是否过度推断？
```

---

## 4. Critic / Debate Assistant

作用：

主动攻击当前理解。

类似：

组会上别人提出质疑：

```
你的假设有什么证据？
有没有遗漏方向？
是不是陷入局部优化？
```

帮助 Scientist 跳出路径依赖。

---

# 6. Scientist 与 Claude 的边界

关键原则：

## Claude 产生信息和能力

## Scientist 产生理解和判断

流程：

```
Claude output

      ↓

Scientist interpretation

      ↓

Research State update
```

而不是：

```
Claude suggestion

      ↓

automatic action
```

否则 Scientist 会重新退化为 coding agent。

---

# 7. 最终理想形态

一个 Scientist：

```
                  Research State

                        ↑

                        |

                  Scientist

                        |

       ---------------------------------

       |              |                |

 Literature       Experiment       Critic

 Claude             Claude           Claude

       |

 Research World
```

Scientist 是研究主体。

Claude 是能力放大器。

---

# 8. Evolution 的位置

在这个定义下：

Evolution 不是为了让多个弱 agent 拼起来。

而是：

> 当单个 Scientist 已经具备完整研究能力后，通过多个 Scientist 并行形成研究群体。

即：

```
Single Scientist:
负责深度和连续性

Evolution:
负责多方向探索和避免认知锁定
```

多个 Scientist 的价值不是：

“一个人提更多 proposal”。

而是：

```
Scientist A:
解释模型 A

Scientist B:
解释模型 B

Scientist C:
解释模型 C
```

不同 Research State 在共享 evidence 中竞争、交流、演化。

---

一句话总结：

> Scientist 的核心不是写代码，而是维护一个不断被证据修正的 Research State；Claude 不替代 Scientist，而作为它的多面能力扩展，让 Scientist 能够像真实研究者一样调查、实验、讨论和验证。Evolution 则是在多个这样的 Scientist 之间扩大探索空间。
