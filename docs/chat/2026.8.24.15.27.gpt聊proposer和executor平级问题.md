明白，你要的不是完整架构文档，而是把刚刚讨论中**几个关键设计转折点**收束下来，作为重构设计说明。可以这样写：

```markdown
# SimpleEvolution Core Design Refinement

## 1. Scientist as the Research Owner

当前设计不再将 Proposer 与 Executor 视为平级角色。

研究过程不应该被拆成：

```
Proposer → Proposal → Executor → Result
```

因为这种拆分会割裂研究上下文，使 Proposer 只负责提出想法，而真正的问题理解、实验反馈和迭代过程被交给另一个 agent，导致 Scientist 无法保持完整的研究连续性。

新的设计中：

> Scientist owns the entire research process.

一个 Scientist 进入一个 Research World 后，应完整推进一次研究：

```
Understand World
        ↓
Form Research State
        ↓
Design Experiment
        ↓
Use Tools / Execute
        ↓
Analyze Evidence
        ↓
Update Research State
        ↓
Conclude or Continue
```

研究结束时，Scientist 提交自己的 Research State，而不是单独提交 Proposal。

---

## 2. Claude Code as Tool, not Research Agent

Claude Code 不再作为独立 Executor 与 Scientist 平行存在。

Scientist 是研究主体，Claude Code 是 Scientist 可以调用的执行工具。

关系变为：

```
Scientist

    |
    +---- Claude Code
    +---- Analysis Tool
    +---- Simulation Tool
    +---- Other Tools
```

Scientist 负责：

- 为什么做这个实验；
- 选择什么方向；
- 如何解释实验结果。

工具负责：

- 实现代码；
- 调试；
- 执行实验。

这样既保留 Scientist 的纯净研究上下文，又利用 Claude Code 成熟的 coding harness 能力。

---

## 3. Research State as the Core Research Artifact

研究过程中真正需要演化的不是 Proposal，而是 Research State。

Research State 表示 Scientist 对当前 Research World 的理解，包括：

- working model；
- evidence；
- hypothesis；
- experiment history；
- 当前判断。

它连接：

```
Problem Understanding
        ↓
Experiment
        ↓
Evidence
        ↓
Updated Understanding
```

Research State 是 Scientist 的连续认知载体。

---

## 4. Node as Research World

Node 表示一个真实、可复现的客观 Research World。

它不是：

- 一个 proposal；
- 一次实验；
- 一个优化结果。

Node 包含：

- 当前代码状态（如 SHA）；
- 环境；
- 实验事实；
- 历史 lineage。

Scientist 在 Node 上研究，最终产生 candidate world。

Harness 根据 candidate SHA 运行真实 evaluation：

```
Research State
        ↓
Candidate SHA
        ↓
Evaluation
        ↓
Gate
        ↓
New Child Node
```

只有被现实验证的改变才能进入 Research Tree。

---

## 5. Supervisor as Research Resource Manager

Supervisor 不负责提出方案，也不负责评价实验。

它的职责类似科研组织中的 PI：

> 决定研究资源应该投入哪些 Research World。

它负责控制 Tree 的演化方向：

- 哪些节点继续深入；
- 哪些方向值得探索；
- 如何平衡 exploration 和 exploitation。

---

## 6. Evolution Object: Research Trajectory, not Solution Search

SimpleEvolution 的目标不是：

```
generate more proposals
```

也不是：

```
find better code patches
```

而是：

```
maintain and evolve multiple research trajectories
```

Tree 记录的是：

不同 Scientist 对问题形成的理解、实验和验证后的研究路线。

核心目标：

> 通过保持多个 Research State，避免单一 Scientist 在长期研究中陷入认知路径依赖，同时保留深入探索能力。
```

这个版本基本就是你刚刚几轮讨论的核心，不引入之前那些容易把系统复杂化的东西（frontier、reviewer、executor hierarchy 等）。重点突出三个变化：

1. **Proposer → Scientist（研究主体）**
2. **Executor → Tool（执行能力）**
3. **Tree → Research World Evolution（研究轨迹演化）**

我觉得这三个才是这次重构真正的核心。
